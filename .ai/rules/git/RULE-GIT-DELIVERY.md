## Исполнитель и разрешение

Все команды Git рабочего слоя, включая чтение состояния, выполняет отдельный
Git-воркер через программный обработчик. Основной агент передаёт задание и
оценивает подтверждённый отчёт; самостоятельно Git не запускает. Продуктовые
SourcePromotion, ReleaseCandidate и их полномочия этим правилом не меняются.

Воркер не наследует историю диалога. Модель выбирается по настройке и указанию
пользователя; текущий выбор — `gpt-5.6-luna` с уровнем рассуждения `low`.
Недоступность модели, обработчика или
доверенного контекста блокирует вызов; замена моделью основного агента или
ручными Git-командами не допускается. Идентификаторы моделей не угадываются.

`inspect` требует разрешённого анализа репозитория. Commit, push и их область
должны быть разрешены пользователем; завершение правки этого разрешения не
даёт. Повторное согласование уже разрешённого действия не требуется.
Полный состав включается только при явно разрешённом полном снимке изменений.

Для подключённых ограниченных воркеров модель получает только инструкцию
[inspect](../../../.codex/prompts/workflows/delivery/git/inspect.md),
[commit](../../../.codex/prompts/workflows/delivery/git/commit.md) или
[push](../../../.codex/prompts/workflows/delivery/git/push.md) и команду.
Полные AGENTS, правила, workflow и навыки ей не передаются.
Основной агент применяет Git-маршрут до запуска; механизм запуска и обработчик
обеспечивают фиксированную рабочую копию, инструменты разрешённого действия
и подтверждённый результат. При доработке этого маршрута синхронизируй инструкцию
и программные ограничения. Исключение не распространяется на разработку или расширение полномочий.

Для записи вызывающая среда связывает контекст с явным запросом пользователя:
область, назначение, результаты проверок и авторство для commit передаются
отдельно от Git-воркера.
Файл контекста — средство передачи, а не доказательство согласия пользователя.
Неполный контекст блокирует запуск; модель не дополняет и не расширяет его.

## Подключение и границы

### Серверный порт чтения MCP

Узкое исключение по [ADR-0017](../../../documentation/architecture/decisions/ADR-0017-internal-mcp-and-server-management.md)
относится к deterministic machine read port существующего `.ai/tools/git-delivery`:
серверный MCP вызывает только status/diff без LLM на каждый RPC. Доверенная
composition задаёт repository root, principal, scope, deadline и лимиты;
политика путей применяется до чтения содержимого. Порт не выполняет запись,
staging, сетевые операции и произвольные команды. Обычные Git-операции
development-агента, включая inspect, сохраняют маршрут отдельного воркера;
использовать machine port для обхода этого маршрута запрещено.

### Маршрут доставки

- Удалённый репозиторий и выбранный HTTPS/SSH берутся из БД интеграций через
  общего серверного владельца. Локальная рабочая копия — из среды запуска.
  Секреты получает только программный исполнитель, без передачи модели,
  записи в URL, исходники, диагностику или отчёт.
- HTTPS использует токен, SSH — настроенный ключ или `ssh-agent`. Подлинность
  сервера проверяется; интерактивная авторизация и автоматическая смена
  транспорта, назначения или учётных данных запрещены.
- Для `inspect` и commit с явным автором БД не нужна. Если автор не передан,
  загрузчик читает его из включённой интеграции до запуска модели, без получения
  токена. Внешняя сеть и проверка подключения для локального commit не нужны.
  Успешное чтение удалённого репозитория не доказывает право push. Отдельный
  полный сетевой preflight нужен при настройке или диагностике соединения.
- Сохраняй чужие изменения и индекс. Случайные материалы, секреты и результаты
  сборки не включаются. Push покрывает весь публикуемый набор коммитов и явную
  ветку; `defaultBranch` не даёт права переключать её или публиковать в неё.
- Этот маршрут не выполняет force push, stash/reset/rebase, PR, merge, deploy
  или попутное исправление кода. Такие действия требуют отдельной задачи.
- Исправление прерванного commit допускается только через явно разрешённое
  восстановление прежнего requestId с актуальными проверками. Обработчик
  доказывает принадлежность индекса и сохраняет принятый снимок до staging;
  назначение, автора, сообщение и состав обязательных проверок не подменяют. Это не разрешает
  изменение содержимого после подготовки дерева или возможного запуска hooks.
- После неизвестного исхода push сначала сверяй назначение. Новая запись
  требует разрешённого восстановления прежней операции и следующего номера
  попытки в доверенном контексте. Его сохранение до push исключает повторную
  отправку тем же заданием. Журнал не сбрасывай, requestId и назначение не подменяй.

## Достаточность проверок

Используй фактические результаты для проверенного содержимого, конфигурации и
зависимостей. Изменение значимых входов отменяет их применимость. Состав файлов
сам по себе не доказывает выполнение тестов; отсутствие результата не означает
успех. При необходимости выбирай проверки по затронутому поведению:

- документы и инструкции — содержание, ссылки, формат и метаданные;
- код — относящиеся к изменению lint, типы и тесты;
- схема — профильные проверки миграций; интерфейс — нужное браузерное evidence.

Команды берутся из актуального проекта. Полный набор тестов и сборка не
запускаются автоматически ради Git. Обязательные hooks и CI сохраняются.
Порядок, восстановление после сбоя и отчёт задаёт связанный workflow;
проверки ниже — критерии конкретного действия, а не дополнительный аудит.
