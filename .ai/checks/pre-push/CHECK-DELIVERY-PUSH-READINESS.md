## Критерии

Применяется внутри обработчика только для `push` и `commit_push`.

- Разрешены назначение и весь публикуемый набор коммитов; хеш и ветка определены.
- Содержимое коммита соответствует проверенному, включая возможные изменения
  hooks; результаты проверок применимы. Повтор тестов без нового основания не нужен.
- При автоматическом verification-маршруте каждому публикуемому OID и required
  check соответствует сохранённый proof подтверждённого commit и совпадающей
  recipe. Отсутствующий proof блокирует действие; тестирование текущего checkout
  не создаёт evidence для прежних коммитов и не расширяет authorization.
- Автоматический verification-маршрут не переносит checks с `reuse: "never"`;
  они блокируют push до модели и сети. Ручной маршрут требует собственного
  действительного evidence точных OID.
- Подключение из БД включено, его ревизия и репозиторий соответствуют заданию и
  рабочей копии. Выбранный HTTPS/SSH настроен по связанному правилу.
- Ветку и назначение не меняли после проверки; запись для восстановления
  сохранена до отправки. Ожидаемая удалённая версия сверяется также при обмене
  непосредственно перед отправкой с сохранением настроенного `pre-push` hook.
  Подготовлен обычный push без force.
- Для восстановления назначена следующая разрешённая попытка прежней операции;
  её номер сохраняется до отправки и не используется повторно. Журнал не сбрасывался.

Невыполненный критерий блокирует push, сохраняя локальный commit. Прохождение
этой проверки ещё не доказывает успешную авторизацию или запись на сервере;
фактический результат устанавливается после push по workflow.
