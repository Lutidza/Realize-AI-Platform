## Критерии

Применяется внутри обработчика для `manage`.

- Контекст связывает запрос, рабочую копию и одну точную операцию с разрешением.
  Модель не назначает параметры или дополнительные команды.
- Чтение имеет явные лимиты; URL и diff не раскрывают секреты. Для адресного
  diff проверены точные относительные пути, для log — ограниченное число записей.
- `log`, `diff` и операции создания/переключения веток отклоняют partial clone
  до чтения объектов: локальное управление не запускает неявный fetch.
- Перед записью удерживается блокировка общего каталога Git; фактические HEAD
  и ветка соответствуют ожидаемым. Lease выдана `@realize/git-runtime`, связана
  с каноническим `git-common-dir` и действительна для текущей операции.
  Исходное состояние записано в журнал.
- `remote-set-url` сверяет прежний URL, сохраняет выбранный транспорт и меняет
  только разрешённый remote. URL не содержит credential. Сетевой доступ и
  изменение настроек интеграции этим действием не разрешаются.
- `worktree-repair` принимает точные разрешённые абсолютные пути; внешние
  worktrees явно перечислены. Список покрывает весь затрагиваемый набор
  существующих зарегистрированных внешних каталогов: штатный repair после переноса
  основной копии может менять все их связи. Неполный список блокируется до записи.
  Метаданные отсутствующих каталогов сохраняются без prune/create; существующий
  каталог с недопустимым `.git` или symlink блокируется.
- Создание ветки использует разрешённое имя и ожидаемый HEAD; создание и
  переключение допускаются только при чистом индексе и рабочей копии, без
  скрывающих изменения index flags и незавершённых Git-операций. Игнорируемые
  файлы не перезаписываются; hooks и submodule recursion отключены.
- Повтор сохраняет исходные requestId и контекст, сверяет журнал с состоянием
  и не выполняет другую запись при конфликте или неизвестном результате.

Невыполненный критерий блокирует соответствующее действие. Тесты приложения,
БД интеграций и авторизация GitHub не требуются для локального управления.
