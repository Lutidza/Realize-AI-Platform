## Применимость

Проверять файлы в области, определённой связанным правилом: новые и изменяемые
исходники, а при рефакторинге — согласованный компонент или модуль целиком.
Проверка выполняется в составе обычного просмотра изменений.

## Условия прохождения

- Каждый применимый файл имеет шапку с непустыми `@file`, `@version`, `@date`
  и `@description` либо подпадает под конкретное исключение правила.
- Путь соответствует файлу; версия и дата оформлены раздельно, в форматах
  правила, без подстановки даты вместо версии. Дата календарно корректна.
- Версия и дата обновлены по фактическому изменению и порядку из правила;
  промежуточные правки не вызвали повторного увеличения версии.
- Описание на русском соответствует одной ответственности файла. Шапка
  не содержит историю изменений и не нарушает работу инструментов.
- Публичные контракты описаны; существенные неочевидные ограничения объяснены.
  Отсутствие комментария у внутреннего `export` оценивается по его контракту,
  а не по самому ключевому слову.
- Устаревшие комментарии исправлены или удалены, обязательные отсутствовавшие
  добавлены. Нет пустых описаний, пересказа типов и очевидных строк кода.
- Ссылки ведут к существующим подходящим документам; `@docref` соответствует
  идентификатору документа и сопровождается `@see`. Отсутствие необязательной
  ссылки само по себе не является нарушением.
- Соблюдены границы задачи и исключения; генерируемый и сторонний код
  не переписан вручную ради шапок.

## Результат

Проверка не пройдена при отсутствии любого обязательного поля, неподтверждённом
исключении или другом невыполненном условии выше. Нарушение указывается
с конкретным файлом; ограничение пользователя не превращает его в соответствие
стандарту.

Достаточно общего результата и существенных замечаний в итоге задачи.
Отдельный отчёт для каждого файла не требуется. Изменение только комментариев
само по себе не требует сборки, браузера или полного набора тестов приложения.
