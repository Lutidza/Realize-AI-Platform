## Выбор проверки

Оценивай только обещанный результат и затронутый scope. Исследование проверяется
по источникам и выводам; runnable UI дополнительно по браузеру и поведению;
тема — по её adapters и потребителям. Документ с будущим UI не требует запускать
несуществующий preview. Эта проверка дополняет действующие frontend checks,
не заменяет их и не регистрирует новую серверную команду.

## Критерии

| Область | Что проверить | Достаточное свидетельство |
| --- | --- | --- |
| Цель | Результат решает основной сценарий и соответствует выбранному типу | Brief → сценарий → конкретный артефакт |
| Источники | Образец действительно изучен; наблюдения отделены от предположений | URL/локальный материал, дата, способ просмотра, применённый паттерн |
| Композиция | Главные действия и информация различимы, группы и плотность соответствуют задаче | Сравнение референса с точной версией и пояснение отклонений |
| Визуальная система | Typography, spacing, цвет, состояния и иконки согласованы | Использованные tokens/primitives и проверка затронутых consumers |
| Данные и поведение | Контролы делают обещанное; demo/persistence/ошибки обозначены честно | Воспроизведённые сценарии; fixtures не выдаются за сохранение в CMS |
| Состояния | Пустой результат, loading/error, длинный текст и интерактивные состояния учтены по scope | Матрица состояний с результатом проверки |
| Адаптивность | Нет потери важных действий/читаемости на целевых ширинах | Browser evidence на выбранных viewport; для новой темы Admin — 1440/768/390 |
| Доступность | Keyboard, focus, labels, контраст и motion учтены по компонентам | Реальная ручная/автоматическая проверка; без необоснованного заявления полной сертификации |
| Переиспользование | Нет второго локального контракта темы; API/props и adapters согласованы | Owner map и пример существующего потребителя |
| Материалы | У assets есть origin, допустимое использование, назначение и alt | Метаданные; неизвестные права не обозначены как подтверждённые |
| Версия | Изменение, preview и evidence относятся к одному результату | Реальные revision/hash/receipt либо честно обозначенные локальные файлы и база проверки |
| Передача | Следующий исполнитель получает scope, ограничения и замечания | Самодостаточный handoff без secrets и несуществующих ссылок |

Для темы проверяй поддержанные light/dark modes, portals/popovers, формы,
таблицы и статусы на целевых adapters. Для одного компонента достаточно его
состояний и затронутых потребителей. Новые темы не принимаются по одному hero
или изображению без галереи реального использования.

## Результат

Для применимых критериев используй `pass`, `fail`, `unverified`; `not_applicable`
с короткой причиной допустим для остальных. По каждому `fail` укажи дефект,
серьёзность, экран/состояние и ожидаемое исправление. `Unverified` содержит
недостающий инструмент/среду и следующий шаг, а не переименовывается в `pass`.

Работа может быть передана как исследование или подготовленная реализация
с ограничениями. Готовность интерактивного результата не подтверждается,
если ключевой сценарий сломан или обязательное browser evidence отсутствует.
Результат включается в общий отчёт задачи; отдельный отчёт каждого этапа
и численная «оценка профессионализма» не нужны.
