# Ограниченное чтение контекста

`read-context.mjs` читает выбранные строки без записи файлов, сети или модели.
Использует закреплённый Node.js проекта без дополнительных пакетов. Из корня:

```bash
node .ai/tools/context-reading/read-context.mjs '[{"path":"README.md","startLine":1,"endLine":null}]'
```

Вход — от 1 до 3 selections одного из трёх форматов:

- `{ "path": "...", "startLine": 1, "endLine": null }` — диапазон строк;
- `{ "path": "...", "section": "## Exact heading" }` — заголовок и его раздел;
- `{ "path": "...", "beforeHeading": "## Exact heading" }` — от начала файла
  до строки перед заголовком.

`section` включает вложенные подразделы и заканчивается перед следующим
заголовком того же или более высокого уровня. Совпадение полное, с учётом `#`,
регистра и текста, без внешних пробелов; нужен ровно один такой заголовок.
Учитываются ATX-заголовки `#`–`######` с отступом до трёх пробелов, вне fenced
code с backticks/tilde. Примеры внутри fenced code не становятся границами.
Setext-заголовки и Markdown-вложения в quotes/lists этим маршрутом не разбираются.
Отсутствующий/дублированный заголовок и пустой `beforeHeading` — `INVALID_INPUT`.
Нельзя смешивать поля разных форматов в одном selection.

Для обычного внешнего worker можно выбрать два раздела одним вызовом:

```bash
node .ai/tools/context-reading/read-context.mjs '[{"path":".ai/workflows/core/worker-session/WORKFLOW.md","section":"## Выбор режима"},{"path":".ai/workflows/core/worker-session/WORKFLOW.md","section":"## Общая последовательность"}]'
```

Для static frontend review без reference используй
`{"path":".ai/workflows/frontend/next-react/guardrail/WORKFLOW.md","beforeHeading":"## От референса к интерфейсу"}`.
Границы вычисляются по текущему файлу, без угадывания `1..100`.

Пути относительны cwd; absolute paths, `..`, каталоги и symlink за пределы cwd
отклоняются. Строки нумеруются с 1 и разделяются LF; CRLF сохраняется в тексте.
`endLine: null` означает EOF, числовой конец после EOF ограничивается EOF.
Пустой файл, начало после EOF, неверный JSON, неизвестные поля и пересекающиеся
диапазоны одного файла считаются ошибкой. Источник должен быть UTF-8.

Успех печатает один compact JSON и завершающий LF:

```json
{
  "sources": [
    { "path": "README.md", "startLine": 1, "endLine": 50, "text": "..." }
  ],
  "pending": [{ "path": "README.md", "startLine": 51, "endLine": 200 }]
}
```

`sources` содержит от 1 до 3 непересекающихся фрагментов. Весь вывод, включая
метки, `pending` и LF, занимает не более 12 288 UTF-8 bytes. Полный фрагмент
проверяется перед поиском допустимого префикса: удаление его записи из `pending`
может уменьшить итоговый размер. Символы Unicode не заменяются ASCII-экранированием.

`sources` и `pending` всегда содержат канонические числовые координаты, даже
при входном выборе по заголовку. Следующему вызову передавай весь массив `pending`
предыдущего ответа, сохраняя
оставшиеся диапазоны. Helper сохраняет порядок и читает повторные пути один раз
за запуск; это не snapshot между запусками. При изменении источника проверь
актуальность координат. Не начинай с целого документа, если нужен его раздел.
Область разрешённого чтения и применимость источников определяет вызывающий агент.

При меньшем лимите инструмента понизь бюджет:

```bash
node .ai/tools/context-reading/read-context.mjs --max-bytes 4096 '[{"path":"README.md","startLine":1,"endLine":null}]'
```

`--max-bytes` принимает целое число от 1 до 12 288, по умолчанию 12 288.
Байтовый бюджет не измеряет токены модели. Неделимая строка вместе с метками
и `pending` может не поместиться: helper сообщает `LINE_TOO_LARGE` в stderr
и возвращает код 3. Ошибки ввода/чтения возвращают код 2. При этих ошибках stdout
пуст и текст источников не выводится. Успех возвращает код 0; остаток обязательного
чтения нельзя считать выполненным до исчерпания соответствующего `pending`.
