# Prompt: Next/React frontend guardrail

Ты выполняешь read-only проверку указанного frontend diff в Realize — AI Platform.
Код и инструкции проекта не изменяй. Сохранять можно только материалы проверки
по `.ai/rules/scope-control/RULE-TASK-WORKSPACE-ARTIFACTS.md`, если они нужны.
Прямой запрет пользователя на любые записи относится и к материалам проверки.

## Загрузка контекста

Перед чтением сверь нужные источники с текстами и диапазонами, уже доступными
в текущем или унаследованном контексте. `AGENTS.md`, переданный средой как полный
текст, уже прочитан; путь, metadata или пересказ не заменяют текст источника.
Учитывай результат каждого чтения сразу: ссылка на тот же документ из другой
роли, registry или workflow не является причиной загрузить его повторно.
Для этого достаточно помнить пути и полученные диапазоны в ходе работы;
отдельный файл учёта не создавай.

- `.ai/roles/developer/frontend/INDEX.md` прочитай один раз, если его текста ещё
  нет в контексте. При частичной выдаче дочитай только отсутствующий фрагмент.
- `.ai/workflows/frontend/next-react/guardrail/WORKFLOW.md` читай по применимому
  разделу и не перечитывай уже полученные диапазоны. Для статического review
  без визуального референса достаточно общего порядка до раздела
  «От референса к интерфейсу»; дизайн-процесс загружай только при его применимости.
- `documentation/project-context.md` целиком не загружай. Если нужный раздел
  ещё не известен, сначала получи только заголовки с номерами строк через
  `rg -n '^#{1,3} ' documentation/project-context.md`. Выбери раздел по предмету
  проверки и прочитай его ограниченный диапазон через `sed -n` либо извлечение
  секции через `awk`, до следующего заголовка того же или более высокого уровня.
  Для обычного `src/components/**` начни с «Технологии и runtime baseline» и
  относящихся к владельцу абзацев «Активный контур приложения». Admin/AI,
  Task Manager, billing и другие разделы нужны только при затронутом контракте.
  Уже доступный нужный фрагмент повторно не извлекай.

Shell-команды здесь — примеры адресного чтения. Доступный MCP с проверкой hash
и `startLine`/`lineCount` подходит так же; отдельная проверочная команда перед
каждым чтением не требуется.

Сначала выбери применимые источники, затем загрузи недостающее и переходи к
проверке кода. Не обходи граф ссылок рекурсивно. Усечённый ответ не считай полным:
уточни только недостающий диапазон. Повторное чтение допустимо при доказанном
изменении источника или потере его текста после compaction; назови причину.

## Проверка и результат

Найди фактического route/component owner и проверь затронутые Server/Client,
data/API и shared UI границы. Используй frontend registry только для применимых
rules/checks. Не требуй полного frontend audit или browser suite, если вывод
не зависит от rendering/interaction.

Верни конкретные findings с paths, влиянием и evidence; укажи существенную
непроверенную часть. Если нарушений нет, скажи это кратко. Другой frontend stack
не вводи; новая зависимость оценивается в scope основного задания.
