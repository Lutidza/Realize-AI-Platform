# Текущий этап Realize — AI CMS

Дата сверки: 12 сентября 2026 года. Тип: датированный отчёт по текущему коду,
документации и рабочему слою агентов. Это не замена целевой спецификации или
активных правил `.ai/`.

## Вывод

Проект находится на **Phase 2 — развитие Change Engine, Data Lane и настройки
агентского слоя**. Базовое приложение и интеграция чата уже созданы. Параллельно
реализовано основание исполнения кода и предпросмотра из Phase 3 и часть
инфраструктуры доставки из Phase 4. Это ещё не завершённый универсальный
конструктор сайтов с безопасной автоматической публикацией.

| Фаза | Фактический уровень | Что означает |
| --- | --- | --- |
| 0 — baseline | Закрыта как исходный этап | Стек, запуск, миграции, CI и основные границы проекта определены |
| 1 — plugin/read-only chat | Реализована | Админский чат, интеграция, API/SSE, история и отдельные runtime-компоненты работают |

## Что уже реализовано

1. **Админский агент и управление подключением.** Продуктовый runtime использует
   интеграцию в админке; настройки моделей, этапов и доступа принадлежат ей.
   Это отдельный контур от Codex, которым разработчик обслуживает репозиторий.
   Владельцы: `src/plugins/index.ts`, `packages/codex-adapter/src/CodexProfile.adapter.ts`,
   `packages/payload-ai-plugin/src/chat-context/`.
2. **Раздел настроек уже шире правил.** В
   `packages/payload-ai-plugin/src/admin/agent-layer-settings/` находятся редакторы
   профилей, инструкций, связей, процессов и версий. API поддерживает черновики
   конфигурации, validation, releases, runtime projection и activation/rollback:
   `packages/payload-ai-plugin/src/endpoints/aiConfigEndpoints.ts`,
   `aiConfigActivationHandler.controller.ts`.
3. **Управляемые операции данных.** Текущий публичный union содержит
   `catalog.assignCategory.v1` и `pages.createDraft.v1`:
   `packages/ai-contracts/src/dataOperations.ts`. Предложение проходит подготовку
   снимка, подтверждение, применение, audit и отдельный откат. Общий процесс
   принадлежит `packages/payload-ai-plugin/src/endpoints/dataOperation*.ts`.
4. **Создание страниц действительно идёт через сервис.**
   `pageDraftCreation.service.ts` проверяет права и slug, применяет подтверждённый
   снимок через Payload и сохраняет фактический результат. Host mapper
   `src/collections/Pages/mapAIPageDraft.mapper.ts` строит разрешённые
   Content/Lexical-поля. Создаётся черновик; автоматически опубликованная страница
   не является результатом этой операции. Общий `lockPageDraftWrites.hook.ts`
   учитывает конкурирующие записи, включая autosave.
5. **Локальный исполнитель запускается вместе с проектом.**
   `scripts/runtime/startDevelopment.controller.ts` и соседние runtime-модули
   управляют Next, control plane и execution worker. Heartbeat и диагностика
   реализованы отдельно от наличия процесса. Это локальный режим разработки;
   его запуск не подтверждает готовность production worker topology.

## Последняя работа и оставшиеся возможности

Исправление защиты storefront preview уже находится в коде:
`src/utilities/preview/`, `/next/preview`, серверное чтение страниц и товаров.
Cookie preview больше не заменяет действующую сессию администратора; Local API
выполняет access checks. Связанные collection-запросы Archive/Carousel также
ограничены опубликованными товарами.

Проверки завершены: 27 адресных тестов, TypeScript, линтер и проверка шапок
успешны. После восстановления окружения реальный Chrome прошёл 34 сценария
с настоящими Payload-сессиями: страницы и товары, draft-only 404, запрет входа
для посетителя и customer, logout с сохранённой preview-cookie, отзыв роли,
HTML/metadata, внутренние переходы и публичные товарные блоки. Проверка
использовала одноразовую копию БД, без изменения основного контента.
Ошибок страницы в завершённом прогоне не зарегистрировано.

`pages.updateDraft.v1` и операция публикации в текущем union отсутствуют.
Их обсуждение и предварительный анализ не означают, что они реализованы.

## Расхождения документации и рабочего слоя

1. **Roadmap Phase 2 отстаёт от кода.** В
   [описании Phase 2](../specifications/realize-ai-commerce/v1.0/05-implementation-roadmap/02-phase-2-change-engine-data-lane.md)
   settings, activation/rollback и run binding ещё перечислены среди остатков,
   хотя соответствующие API, UI и runtime уже существуют. Там же не отражён
   второй адаптер `pages.createDraft.v1`. Статус «Phase 2 в работе» остаётся
   обоснованным, но перечень выполненного и остатка требует синхронизации.
2. **Правило жизненного цикла и процедура запуска противоречат друг другу.**
   `.ai/rules/agent-runtime/RULE-WORKER-SESSION-LIFECYCLE-AND-AUTONOMOUS-MODE.md`
   допускает native collaboration и необязательный managed runtime.
   `.ai/workflows/core/worker-session/WORKFLOW.md` всё ещё требует только
   `codex exec` и запрещает `spawn_agent`; прежние требования сохранены и в
   `.codex/skills/codex-external-worker-session/SKILL.md`.
3. **Карта состояний содержит лишние обязательные переходы.**
   `.ai/system/state-machine.md` перечисляет `human_approval` и `commit_push`
   в общей цепочке, тогда как `.ai/workflows/core/main-delivery/WORKFLOW.md`
   выбирает применимые проверки и delivery только для разрешённого действия.
   Это долг согласования инструкций, а не основание выполнять незапрошенный push.
4. **В runtime README остались отсутствующие ссылки.**
   `.ai/tools/agent-runtime/README.md` ссылается через `source_spec` и
   `monitor_spec` на прежний `documentation/project/specs/ai-engineering-workflow/`.
   Отсутствие базы optional managed runtime само по себе не означает поломку
   продуктового агента или штатных подагентов текущей среды.
5. **У development Git worker обнаружена реальная регрессия транспорта.**
   Общий `JsonLineRPCClient` требует явный `CODEX_HOME`, но Git adapter передавал
   очищенное окружение без него. Штатный inspect завершился
   `worker_transport_failed`, не выполнив ни одной Git-операции. Исправление
   выполнено у Git worker: профиль локального CLI задаётся явно через
   `REALIZE_GIT_CODEX_HOME`; без него запуск закрыт. Общий транспорт и админский
   runtime не получили fallback на авторизацию хоста. После исправления
   штатный inspect успешно выполнил обработчик Git; 28 адресных тестов прошли.

Аудит выявляет эти несоответствия; массовое переписывание `.ai/` и `.codex/`
в эту задачу не включено. Статические документы не доказывают выполнение
тестов, миграций, push или внешнего развёртывания.

## Обоснованный следующий этап

Preview proof и регрессия Git worker закрыты в ходе этой работы. Следует
согласовать перечень выполненного в Phase 2 и противоречащие процедуры
рабочего слоя.
Следующее продуктовое расширение — **редактирование существующего черновика
с точным diff до/после и подтверждением конкретной версии**.

Для него недостаточно повторно вызвать mapper создания страницы: полная замена
`layout` способна потерять медиа, формы и связи. Нужны ограниченный контракт
чтения текущей страницы, операции над поддерживаемыми полями и блоками,
сохранение остальных данных, проверка конкурентных изменений и безопасный
откат. После этого — отдельное утверждение и публикация точной версии,
с проверкой прав, маршрута и обновления кэша. Публикацию нельзя подменять
созданием черновика или общим разрешением выполнять код.

Полная готовность Phase 4 требует недостающего production authorization/controller,
изоляции credentials, durable rollout/recovery, health gates и подтверждённого
пилота; эти ограничения явно перечислены в
[Phase 4](../specifications/realize-ai-commerce/v1.0/05-implementation-roadmap/04-phase-4-production-delivery.md).
