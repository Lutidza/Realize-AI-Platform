# Допуск рабочего адаптера OpenAI Chat Completions

Для назначения в режиме `static-read-only` оркестратор выбирает адаптер `openai-chat-completions` и модель. Команда `preflight-api` принимает путь к lock-файлу выбранного назначения, `contextId` успешного `bind` и идентификатор модели. Адаптер повторно открывает контекст и проверяет окончательный HTTP-запрос внутри Realize. [Контракт V1](adapter-access-evidence-v1.md) · [Адаптер](../../../.ai/tools/worker-assignment/src/adapters/openAiAuditRequest.adapter.ts)

## Источник и границы политики

Потребители импортируют профиль `openAiChatPolicy` и функцию выбора `resolveOpenAiChatPolicy` через `realize-ai-platform/model-providers/openai-chat-completions-policy`. Путь объявлен в [манифесте платформы](../../../package.json).

OpenAI описывает список инструментов Chat Completions в параметре `tools`. В режиме function calling модель возвращает имя функции и аргументы, а приложение вызывает обработчик. Карточка GPT-5.4 mini подтверждает совместимость модели с этим API и поддержку функций. [Контракт Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) · [Вызов функций](https://developers.openai.com/api/docs/guides/function-calling) · [Карточка модели](https://developers.openai.com/api/docs/models/gpt-5.4-mini)

Realize хранит проверенный профиль в реестре политик провайдера. Для выбора записи должны одновременно совпасть провайдер `openai`, метод `POST`, адрес `https://api.openai.com/v1/chat/completions` и снимок модели `gpt-5.4-mini-2026-03-17`. Для этой комбинации зарегистрирована политика `explicit-functions-only`. В отчёт попадает применённая запись `providerPolicy` с её `id`, `revision` и ссылками на первоисточники. При отсутствии записи для выбранной комбинации `providerPolicy` равна `null`. Изменение области политики требует проверки контракта провайдера и новой ревизии записи. [Регистрация и выбор политики](../../../services/ai-control-plane/src/model-providers/openaiChatCompletions.policy.ts)

Новые отчёты содержат `providerPolicy.id` со значением `openai.chat-completions.explicit-functions-only`. Ранее сохранённый JSON содержит имя политики на момент проверки и читается в исходном виде. Ревизия политики при переименовании осталась равной `1`. При восстановлении попытки адаптер заново проверяет запрос и сравнивает ревизию действующей политики с `policyRevision` из контрольной точки. [Проверка при восстановлении](../../../.ai/tools/worker-assignment/src/checkpoints/prepareCheckpointRequest.service.ts)

## Проверка запроса

1. Адаптер формирует тело из `model`, `messages` и `tools`. Первое сообщение содержит проверенный ввод назначения. Для продолжения валидатор сверяет каждую пару `assistant`/`tool` с подтверждённым чтением той же попытки, включая `tool_call_id`, порядок и содержимое сообщений.
2. В `tools` разрешена одна прямая функция `repo_read_file`. Схема функции должна совпасть с объявлением обработчика, а `path.enum` — с полным набором путей из `effectiveAccess.readPaths` выбранной привязки. Он включает обязательные источники и файлы области ревью. Лишний, пропущенный или подменённый путь блокирует допуск.
3. Валидатор проверяет, что запрос использует обработчик этого контекста. Для каждого разрешённого пути он выполняет контрольное чтение и сверяет путь и SHA-256 файла с `readPins`. Обращения за пределы разрешённого набора и попытка записи должны вернуть `FORBIDDEN`.
4. Допуск связывается с текущими `attemptId` и `requestId`, проверенными байтами запроса и тем же обработчиком. Для продолжения в той же попытке создаётся новый запрос со своим допуском. [Проверка окончательного запроса](../../../.ai/tools/worker-assignment/src/admission/inspectApiAuditAdmission.service.ts)

## Что означает результат

| Ситуация | Результат |
| --- | --- |
| Профиль зарегистрирован, проверены пакет и все права | `ready`, код CLI 0 |
| Выбран алиас модели или иной снимок вне проверенного профиля | `blocked / access_unverified`, код CLI 2 |
| Изменился каталог инструментов или в схеме функции указан другой набор путей | `blocked / transport_access_mismatch`, код CLI 2 |
| Контекст недоступен, изменился закреплённый файл или нарушен контракт доступа | `blocked` с причиной от проверки привязки или V1, код CLI 2 |

`ready` подтверждает полномочия подготовленного запроса. Источником сведений о провайдере служит зарегистрированный контракт API. Доступ конкретного аккаунта к модели, состояние сервиса и ответ провайдера проверяются только при фактической отправке.

Программная отправка первого запроса повторно открывает контекст, создаёт свою попытку и проходит ту же проверку. В HTTP поступают байты допущенного запроса на зарегистрированный адрес, перенаправления запрещены. При `blocked` адаптер возвращает отчёт до отправки. Эту границу проверяет тест с подменой `fetch`. [Проверки адаптера](../../../.ai/tools/worker-assignment/test/openAiAuditRequest.test.ts) · [Команды CLI](../../../.ai/tools/worker-assignment/README.md#рабочий-адаптер-openai-chat-completions)

При восстановлении процесса адаптер заново открывает привязку, проверяет права, восстанавливает результаты чтения по закреплённым исходникам и сверяет их хеши с историей попытки. Каждый окончательный запрос продолжения проходит новый допуск V1. При проверке восстановления доставку подтверждает локальный имитатор.
