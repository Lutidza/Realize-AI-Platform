# Допуск рабочего адаптера OpenAI Chat Completions

Для аудита формы «Создать статью» оркестратор выбирает адаптер `openai-chat-completions` и модель. Команда `preflight-api` проверяет подготовленный HTTP-запрос внутри Realize. Для проверки достаточно сохранённого контекста. [Контракт V1](article-audit-evidence.md) · [Адаптер](../../../.ai/tools/worker-assignment/src/adapters/openAiAuditRequest.adapter.ts)

## Источник и границы политики

OpenAI описывает список инструментов Chat Completions в параметре `tools`. В режиме function calling модель возвращает имя функции и аргументы, а приложение вызывает обработчик. Карточка GPT-5.4 mini подтверждает совместимость модели с этим API и поддержку функций. [Контракт Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) · [Вызов функций](https://developers.openai.com/api/docs/guides/function-calling) · [Карточка модели](https://developers.openai.com/api/docs/models/gpt-5.4-mini)

На этом основании Realize хранит в коде проверенный профиль `openai.chat-completions.article-audit`, ревизия 1. При проверке адаптер ищет точное совпадение провайдера `openai`, метода `POST`, адреса `https://api.openai.com/v1/chat/completions` и модели `gpt-5.4-mini-2026-03-17`. В отчёте `providerPolicy` содержит применённую запись, ревизию и ссылки на первоисточники. Для незарегистрированного сочетания значение равно `null`. Изменение области политики требует проверки контракта провайдера и новой ревизии записи. [Регистрация политики](../../../services/ai-control-plane/src/model-providers/openaiChatCompletions.policy.ts)

В пределах профиля адаптер формирует тело из идентификатора модели, сообщений и одной функции `repo_read_file`. Первое сообщение содержит проверенное назначение. В продолжениях следуют упорядоченные пары вызовов и результатов чтения той же попытки. Общая проверка V1 отклоняет посторонние поля и инструменты, сверяет `path.enum`, обработчик и SHA-256 всех 18 файлов, затем проверяет запрет чтения соседнего пути и записи. Адрес и тело принадлежат одной попытке. HTTP-транспорт запрещает перенаправления. [Проверка окончательного запроса](../../../.ai/tools/worker-assignment/src/admission/inspectApiAuditAdmission.service.ts)

## Что означает результат

| Ситуация | Результат |
| --- | --- |
| Профиль зарегистрирован, проверены пакет и все права | `ready`, код CLI 0 |
| Выбран алиас модели или иной снимок вне проверенного профиля | `blocked / access_unverified`, код CLI 2 |
| Контекст недоступен, изменился закреплённый файл или нарушен контракт доступа | `blocked` с причиной от проверки привязки или V1, код CLI 2 |

`ready` подтверждает полномочия подготовленного запроса. Источником сведений о провайдере служит зарегистрированный контракт API. Доступ конкретного аккаунта к модели, состояние сервиса и ответ провайдера проверяются только при фактической отправке.

Программная отправка первого запроса повторно открывает контекст, создаёт свою попытку и проходит ту же проверку. В HTTP поступают байты проверенного запроса. Если допуск закрыт, операция возвращает отчёт до обращения к сети. Приёмку этой границы выполняет локальный перехватчик HTTP. [Интеграционные тесты](../../../.ai/tools/worker-assignment/test/openAiAuditRequest.test.ts) · [Команды CLI](../../../.ai/tools/worker-assignment/README.md#рабочий-адаптер-openai-chat-completions)

При восстановлении процесса адаптер заново открывает привязку, проверяет права, восстанавливает результаты чтения по закреплённым исходникам и сверяет их хеши с историей попытки. Каждый окончательный запрос продолжения проходит новый допуск V1. Доставку в пилоте подтверждает локальный имитатор.
