# Допуск адаптера к назначению Realize

**Статус.** Архитектурный контракт согласован. Владелец решения о передаче задачи — оркестратор Realize. Контракт применяется и к внешнему агенту, и к исполнителю, которому Realize предоставляет модель через API.

## Ответственность

Оркестратор определяет роль, ревизию назначения, пакет инструкций, права и критерии результата. [Model Router](../../specifications/realize-ai-commerce/v1.0/01-architecture/41-model-garden-and-router.md#414-решение-model-router) выбирает совместимую модель в пределах политики платформы. Адаптер отвечает за фактические возможности выбранного исполнителя. Версия CLI или библиотеки помогает воспроизвести наблюдение.

## Что подтвердить до передачи

| Предмет | Что сверяет оркестратор |
| --- | --- |
| Назначение и пакет | Для одного сочетания `assignmentId`, `revision`, `contextId` и `lockSha256` доверенный компонент Realize повторно открыл подготовленный ввод. Требуемые тексты, их объём и SHA-256 совпадают с источниками назначения. На этой стадии подтверждено наличие пакета в Realize. Факт отправки исполнителю возникает при запуске. |
| Выбранный исполнитель | Адаптер подтверждает провайдера и модель либо согласованный профиль исполнения, к которым привязана конкретная попытка. Оркестратор сверяет их со своим решением о выборе. |
| Эффективные права | Доверенный адаптер сообщает, как установил полный набор доступных инструментов и способов их вызова, операции и область данных. Оркестратор сверяет их с назначением. Обработчик технически отклоняет обращения за пределами выданных прав. Инструкция модели, перечень желаемых прав или частичный каталог сами по себе такого подтверждения не дают. |
| Действие проверки | Среда исполнения связывает подтверждение с живой сессией и её проверенными инструментами либо с подготовленным запросом API и его обработчиками. Эту связь проверяют при передаче. Закрытие сессии, смена исполнителя, инструментов, пакета или закреплённых версий требует новой проверки. При изменении возможностей во время исполнения дальнейший вызов допускается только после сверки. |

Подтверждения приходят из доверенного адаптера и хранилища подготовленного контекста Realize. В решение входят проверенные сведения о правах и недостающее покрытие. Текст задачи, ответ модели и отчёт другой попытки не служат источниками полномочий.

## Решение и передача

1. Оркестратор выставляет `ready`, когда пакет полон, исполнитель соответствует выбору, права полностью подтверждены и привязка действительна для передачи.
2. При неполном подтверждении или расхождении оркестратор выставляет `blocked`, указывает причину и сохраняет пакет в Realize. Отказ относится к выбранной попытке. Для другого разрешённого исполнителя нужна собственная проверка.
3. Отправить пакет можно только в рамках порученного запуска. Проверка привязки и передача должны исключать подмену исполнителя или расширение прав между этими операциями.

В текущем инструменте `bind` проверяет локальный контекст. Решение о допуске конкретного исполнителя принимает общий валидатор `AdapterAccessEvidenceV1`. Для Codex доступны сведения MCP, для подготовленного запроса API проверяются тело запроса, диспетчер и политика инструментов выбранного провайдера.
