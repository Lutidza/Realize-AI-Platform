# Интеграция GPT — Codex

Codex настраивается в `/admin/integrations/codex`. Подключение `codex:primary`
используют чат CMS, исполнитель изменений и независимый проверяющий.
Git-воркер операционного слоя сохраняет собственную настройку запуска.

## Авторизация

- **Вход через браузер:** администратор открывает ссылку OpenAI и подтверждает
  доступ аккаунта ChatGPT. Разрешение входа по коду устройства не требуется.
- **Код устройства:** администратор получает одноразовый код и вводит его на
  странице OpenAI. В настройках безопасности ChatGPT должен быть разрешён вход
  Codex по коду устройства; для рабочего пространства действуют его разрешения.
- **API key:** ключ вводится в поле с маскировкой и передаётся только серверу.
  API оплачивается отдельно от подписки. Пустое поле сохраняет существующий
  ключ только при неизменном способе авторизации.
- **Codex access token:** токен с доступом к Codex для рабочего пространства
  ChatGPT Business или Enterprise. Администратор разрешает его создание;
  источник доступа — соответствующая учётная запись рабочего пространства.
- **Workload identity:** сервер получает краткоживущий доступ через OIDC или
  SPIFFE. Требуются управляемое рабочее пространство, правило доверия и
  включение beta-возможности со стороны OpenAI.

Способ доступа сохраняется явно, автоматического переключения оплаты нет.
Google, Apple, Microsoft и SSO используются на странице входа ChatGPT;
отдельные режимы интеграции для них не создаются. Используется официальный
Codex App Server, внутренний экспериментальный импорт OAuth-токенов не применяется.
Источники:
[авторизация](https://developers.openai.com/codex/auth),
[протокол](https://developers.openai.com/codex/app-server),
[access tokens](https://learn.chatgpt.com/docs/enterprise/access-tokens),
[workload identity](https://learn.chatgpt.com/docs/enterprise/workload-identity).
Совместимость проверена с CLI `0.153.4`.

Проверка читает лимиты аккаунта либо каталог моделей API. Запрос к модели не
выполняется; наличие средств и доступ ко всем моделям не подтверждаются.
Для API-проверки требуется разрешение чтения моделей.

## Хранение и выполнение

Существующая коллекция интеграций хранит настройки, ревизию и результат проверки.
Для ChatGPT и API key сохраняется зашифрованный штатный `auth.json`; для Codex
access token — отдельная зашифрованная запись с типом `codexAccessToken`.
Общий AES-256-GCM vault привязывает секрет к провайдеру и подключению. Workload
identity не сохраняет credential в БД; при переходе к нему предыдущий секрет
удаляется. Схема БД не меняется. DTO содержит режим, способ входа ChatGPT,
разрешённые сведения об аккаунте и признак наличия сохранённого credential.

`packages/codex-adapter` владеет RPC и профилем. Модуль
`packages/payload-ai-plugin/src/integrations/codex/` управляет входом,
сохранением и проверкой; его `runtime/` предоставляет авторизацию исполнителям.
SQL остаётся в `IntegrationRuntimeRepository`.

Запись, проверка и запуск используют общую блокировку PostgreSQL. При занятом
подключении действие отклоняется с предложением повторить его. Обновлённый
credential сохраняется с проверкой исходной ревизии и envelope. Отсутствующее,
отключённое или повреждённое подключение блокирует запуск CMS; личный профиль
и переменные с API key не служат заменой.

## Серверное окружение

Next/Payload, control plane и worker используют одну БД и постоянный
`REALIZE_CODEX_STATE_ROOT`. Для способов с сохраняемым credential у всех
процессов должен быть одинаковый `REALIZE_INTEGRATIONS_ENCRYPTION_KEY`;
workload identity не требует vault.
Путь абсолютный, по умолчанию `~/.local/share/realize-ai-cms/codex`. Нескольким
контейнерам нужен общий том и согласованный системный пользователь. Независимые
установки CMS должны иметь разные каталоги. Codex CLI берётся из `PATH` либо
из `REALIZE_CODEX_BINARY`.

В подкаталоге `runtime/` сохраняется история для `thread/resume`. На время
запуска ChatGPT/API credential записывается с правами `0600` в каталог `0700`,
после синхронизации удаляется. Codex access token передаётся в окружении только
запускаемого процесса через `CODEX_ACCESS_TOKEN`, без записи `auth.json`.
Личный `~/.codex` не читается и не изменяется. Унаследованные переменные другого
способа авторизации исключаются при создании окружения.

### Серверная идентификация

Оператор задаёт `REALIZE_CODEX_FEDERATION_RULE_ID` и
`REALIZE_CODEX_IDENTITY_TOKEN_FILE` всем процессам CMS, использующим Codex.
Адаптер передаёт их как штатные `OPENAI_FEDERATION_RULE_ID` и
`OPENAI_IDENTITY_TOKEN_FILE` только при сохранённом режиме `workloadIdentity`.

Файл токена находится вне checkout, имеет абсолютный путь, принадлежит
системному пользователю процессов CMS и использует права `0400` или `0600`;
каталог — `0700`. Символические и дополнительные жёсткие ссылки не допускаются.
Инфраструктура обновляет файл до истечения токена. В форме доступны состояние
готовности сервера и повторная проверка, без чтения токена или ввода пути.
Готовность конфигурации не подтверждает принятие токена OpenAI: для этого после
сохранения используется отдельная проверка доступа.

Для запусков с workload identity адаптер выбирает профили разрешений Codex,
запрещающие инструментам чтение каталога токена. Профили сохраняют требуемый
режим работы исполнителя или проверяющего.

### Браузерный вход на удалённом сервере

Штатный Codex принимает возврат OpenAI на `http://localhost:1455/auth/callback`.
На одном компьютере вход завершается автоматически. Для удалённого размещения
можно использовать перенаправление порта SSH либо раскрыть в форме блок
завершения входа и передать полный адрес, на который OpenAI перенаправил браузер.

Передача адреса через форму — адаптация CMS поверх локального callback Codex.
Защищённый POST привязан к владельцу и действующей попытке входа; сервер
проверяет исходный адрес возврата, OAuth state и однократность передачи.
Принимается только фиксированный callback текущего процесса, перенаправления
не выполняются. Адрес с одноразовым кодом не сохраняется в аудите и не
возвращается через DTO. На обслуживающем сервере одновременно допускается
один браузерный вход из-за общего порта Codex. Отдельная блокировка PostgreSQL
согласует вход между процессами одной установки и освобождается после закрытия
процесса авторизации. Порт `1455` должен быть доступен этому процессу; вход по
коду устройства его не использует.

Старые native threads из личного профиля автоматически не переносятся. Для
диалога, начатого до перехода на интеграцию, создайте новый чат; сообщения
предыдущего диалога в CMS сохраняются.

Вход использует временный профиль, принадлежит начавшему его администратору и
ограничен десятью минутами. Отмена, ошибка и истечение срока закрывают процесс.
Новая попытка заменяет предыдущую попытку этого администратора. Допускается
восемь активных входов на процесс. Результат сохраняется однократно при опросе
формы, с повторной проверкой прав и ревизии.

Незавершённые входы хранятся в памяти сервера: нескольким репликам требуется
закрепление запросов за репликой на время входа. После перезапуска вход
повторяется. Сбой БД при обновлении токенов приводит к ошибке синхронизации и
может потребовать повторного входа. Пароль ChatGPT, OAuth-токены и сохранённый
API key и Codex access token не возвращаются через Admin/API.

Завершение входа ожидает два штатных события: успешное `account/login/completed`
и последующее `account/updated` для ChatGPT. Только после обновления аккаунта
читаются профиль и credential. Ошибки различают отказ OpenAI, получение аккаунта
и чтение серверного credential. Журнал содержит только этап, способ входа и
фиксированный код причины; текст внешней ошибки, коды и URL в него не попадают.
