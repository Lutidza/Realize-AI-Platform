# Системный шаблон админки Realize

Версия: 0.46, 2026-10-12. Потребители — Task Manager Foundation, reference и Мастерская.

## Ответственность и границы

`packages/template-realize/src/layouts/admin/` владеет компоновкой Realize: глобальная
панель модулей, дополнительная навигация раздела, шапка/действия, рабочая область,
footer, адаптивная навигация, тема и типографический baseline. Компонент использует
React и общие primitives; он не импортирует Next, Payload, коллекции или API.
Модули передают навигационные элементы, содержимое и callbacks через props.
Общий dialog/portal и варианты tabs принадлежат UI-kit. Базовые компоненты
сохраняют самостоятельное использование; в template host Button/Input разрешаются
через выбранный adapter, без зависимости UI-kit от конкретного Realize package.

## Штатный и пакетный интерфейсы Admin

Действующая настройка Admin выбирает штатный интерфейс Payload либо пакетный
интерфейс Realize. Другие совместимые шаблоны расширят этот каталог. Для первой пары Payload ↔ Realize второй
собственный пакет не нужен. Payload UI поддерживается поставщиком CMS и обновляется
с согласованными Payload-зависимостями; копии его layout/styles в template package нет.

Host определяет доступность вариантов для конкретного клиента и основной вход.
Native Admin может не использоваться; это не отменяет Payload backend, API и ACL.
Неактивный или запрещённый host policy вариант не служит неявным обходом выбора
или прав доступа. Возврат в native допускается только при разрешённой доступности.

Выбор оболочки отделён от custom template/palette/settings и light/dark. Native
использует собственные RootLayout/providers/styles, Realize — независимый root.
SDK-контракт применяется к пакетным renderers; host-адаптер штатной оболочки не
имитирует совместимость через фиктивный template manifest. Переход между roots
должен сохранять custom assignment для возврата и защищать drafts/pending команды.

Реализованы и внедрены отдельный persisted shell lifecycle и основной вход: native
dashboard `/admin` после auth возвращает штатный `DefaultDashboard` или переводит
в независимый `/system`. Workspace имеет реальные переходы к Task Manager,
Мастерской и `/system/appearance`; настройки содержат shell picker, отдельные
prepare/preview/apply/recover и историю. Это не вложение Realize в native layout
и не автоматический перенос остальных редакторов Payload. Shell state/ledger
имеет отдельный scope; `ExtensionAssignment` описывает только пакетное назначение.
Основной runtime использует проверенный bundle `_HmknEVf1nCPefAPVruPV`; раздел
`/system/appearance#appearance-installed` показывает Payload `3.88.0` и Realize
`0.1.0` с подтверждёнными версиями, defaults и effective активностью.
Native вход, настройки/preview, фактическое переключение и возврат проверены
[live приёмкой текущего среза](../specifications/extension-management.md#раздел-установленных-шаблонов).
Host availability также фильтрует native ссылки в Realize; session
и роль проверяются каждым protected page и API. [Контракт defaults и policy](../specifications/extension-management.md#контракт-первого-переключателя-оболочек). Realize пока использует native login/unauthorized: полное отключение
штатного UI требует самостоятельных auth/status страниц и проверки backend auth.
Reference всегда остаётся на фиксированном Realize preset независимо от выбора Admin.

## Единый контракт и пакетная граница

`@realize/template-contracts` владеет строгим manifest API, совместимостью и
точным выбором template/palette/mode; `/react` — общим presentation contract,
необязательными capabilities и native props заменяемых Button/Input.
Один контракт содержит различимые Admin workspace/auth/status и frontend page.
Первый `@realize/template-realize@0.1.0` объявляет только Admin; готового frontend
renderer пока нет. Его `/admin` экспортирует compiled definition, `/manifest` —
serializable паспорт без CSS, `/ui` — детали фиксированного Realize reference.

`SystemAdminTemplateProvider` выбирает известную definition из compiled registry,
проверяет compatibility и settings и передаёт UI context также dialogs вне shell.
Защищённые страницы Task Manager и Мастерской инициализируют page-level provider
проверенным `context.initialTheme` до первого render. Provider охватывает controller
и sibling dialogs; root provider служит общим fallback. Callback смены mode
обновляет provider и доменный controller без перемонтирования страницы.
`SystemAdminTemplateHost` передаёт semantic navigation/capabilities/breadcrumbs/actions
выбранному Renderer. Working Task Manager и Workshop не импортируют concrete
renderer. Reference сохраняет явный Realize preset и прежние взаимодействия.

Полный layout, toolbar, navigation, private components, palette и settings
находятся в template package. UIKit хранит общий baseline и объявленно наследуемые
default UI/tokens; Realize navigation tokens/scrollbar принадлежат его palette.
`UiTheme` получает palette identity/class/style через React context, включая
portals, и сохраняет явно переданный mode. Реальные settings `density` и
`panelWidth` проверяются strict schema; JSON Schema генерируется из того же source.
Default comfortable/280 сохраняет референсную геометрию.

Шаблоны — React components, совместимые с Next App Router, SSR и client hydration.
Права, cookies и бизнес-команды остаются у host/модуля. Выбор compiled шаблона читается сервером из appearance storage менеджера расширений;
при отсутствии source migration используется исходный config без записи в БД.
Экран `/system/appearance` имеет навигацию к оболочке Admin, установленным шаблонам,
назначению и истории;
готовит план, открывает actor-bound предпросмотр
`/system/appearance/preview/[planId]`, применяет назначение с CAS и сохраняет
immutable receipt. Admin/frontend имеют отдельные revisions; frontend renderer
ещё не зарегистрирован. Установка нового кода и Workshop package release требуют
отдельного проверенного delivery adapter и этим этапом не реализованы.
Режим из валидной пользовательской cookie имеет приоритет над режимом назначения.
Сохранение назначения не заменяет renderer в открытой странице: новое оформление
загружается при следующем переходе. Reference route использует фиксированный
preset и не читает рабочее назначение.
Обычная смена mode сохраняет controller state. Для смены типа renderer с drafts
Workshop ещё нужен guard либо выделенный controller; готовая hot activation
с сохранением всех состояний не заявляется.

`secondaryNavigation` принимает готовое содержимое или функцию
`(onNavigate) => ReactNode`. Модуль вызывает callback после выбора проекта,
списка или архива: на мобильном экране shell закрывает панель и возвращает
фокус кнопке открытия; на широком экране callback ничего не меняет. Создание
сущности и другие ненавигационные действия сами по себе панель не закрывают.

Общий диалог запоминает открывший его элемент до autofocus дочерних полей.
После закрытия вложенных окон он возвращает фокус доступному исходному элементу
после завершения cleanup focus scopes; открытие следующего диалога имеет
приоритет и не перехватывается восстановлением из закрытого окна.

Доменные поля/формы/состояние задачи остаются у task manager. Изменение shell
не требует копирования интерфейсов модулей. Общие hover/focus/padding contracts
задаются в primitives; локальные CSS отвечают за раскладку, не заменяют кнопки.

## Общая панель разделов

Глобальная навигация принадлежит `SystemAdminNavigation` в пакете Realize и не зависит
от task manager. Host registry `src/components/admin/system-shell/systemAdmin.navigation.tsx`
задаёт порядок, полные названия, Lucide-иконки и известные переходы.
Панель предназначена для замены основной навигации Payload при постепенном
переносе экранов в системный шаблон; её визуальная реализация не дублируется
в отдельных модулях. Этот этап не подменяет Nav во всех существующих Payload views.

Порядок: Главная → AI → Задачи → Планер → CRM → Магазин → Контент → Маркетинг →
Аналитика → Темы и шаблоны → Мастерская → Инструменты → Плагины и пакеты → Интеграции →
Пользователи → Настройки системы → Документация. Повтор CRM в исходном списке пока трактуется
как один раздел; уточнение пользователя может изменить вторую позицию.
Мастерская открывает `/system/workshop`: личные дизайн-проекты, бриф, материалы,
виртуальные файлы и версии. Полный runtime описан в
[спецификации Мастерской](../specifications/design-workshop.md).
Её host использует общий shell, groups, preferences, контекстную строку и тему;
переносимый клиент Payload AI plugin владеет своим workflow и HTTP state.
`SystemAdminPayloadEntry` связывает Payload «Рабочая область» с Мастерской,
референсом, рабочими задачами и экраном «Темы и шаблоны»; доступ к каждой странице проверяется сервером.
«Темы и шаблоны» открывает `/system/appearance` в выбранном standalone шаблоне.
Контракт операций и ограничения установки описаны в
[менеджере расширений](../specifications/extension-management.md).
Подпункты Главной, AI и Задач описаны ниже; остальные разделы пока
сохраняют краткое описание и существующие переходы.

«Аналитика» получила рабочий переход `/admin/analytics/ai` и подпункт
«Расходы ИИ» в группе «Искусственный интеллект». Host registry навигации
ссылается на Payload view плагина, не переносит его данные и формы в shell.
В Payload этот же view доступен из группы «Аналитика». Владелец отдельно
открывает `/admin/analytics/ai/platform` после серверной проверки прав.
Прежний запланированный пункт расходов в группе AI удалён; у раздела один
владелец навигации. Совместимые `/admin/ai/usage` пути сохранены.
Контракт дашборда — [§28.6](../specifications/realize-ai-commerce/v1.0/04-commercial-and-operations/28-observability.md#286-раздел-аналитика--расходы-ии).

Rail занимает 74px: цветная навигация 58px и симметричные поля по 8px.
Цветная панель имеет тёмный неоновый фиолетовый фон в обеих темах,
скруглённые края и иконки одного стиля. Видимых подписей
у кнопок нет: полное имя остаётся в aria-label и заголовке бокового меню.
CRM обозначает деловой портфель (клиенты и сделки), Контент — публикации,
Мастерскую — волшебная палочка, Документацию — раскрытая книга. Все иконки принадлежат Lucide.

Меню прокручивается независимо от рабочей области. Непрокручиваемый внутренний
отступ 6px одинаков со всех сторон; между кнопками также 6px. Содержимое
строго обрезается областью списка. Scrollbar скрыт, чтобы не сужать кнопки
и не нарушать равные боковые отступы; wheel, touch и клавиатурная прокрутка
сохраняются. Блок логотипа занимает ту же высоту 52px, что и topbar;
цветная панель начинается с отступом 8px от нижней границы topbar. Нижние пункты,
включая Документацию, доступны на невысоких экранах.

Верхняя панель начинается сразу после rail с мини-логотипом (x = 74px), охватывая
всю оставшуюся ширину. Вместе с rail она образует единую Г-образную поверхность.
Под ней, справа от rail, находится общий body: внутренняя навигация и workspace.
Его верхний левый угол (x = 74px, y = 52px) имеет круговое скругление 22px, которое
формирует плавный вогнутый стык верхней и левой панелей. Скругление принадлежит
всей внутренней области, а не только контенту справа от навигации.

Body имеет равные поля по 8px со всех сторон — половину --ui-layout-gap.
Внутренняя навигация начинается на x = 82px, y = 60px, на одном уровне с цветной,
и заканчивается за 8px до низа viewport. Между видимыми цветной и внутренней
панелями получается 16px; между sidebar и видимым контентом workspace также 16px.
Верхний и нижний левые углы body равны radius панели плюс поле рамки (14px + 8px):
центры соответствующих дуг совпадают, промежуток остаётся равномерным.
Название рабочей
среды находится в переключателе верхней панели. Внутренняя панель и обычный flyout
имеют одинаковые ширину 280px, высоту и скругление 14px; открытый flyout полностью
перекрывает внутреннюю навигацию. SystemAdminPanel.module.css владеет их общей
формой, поверхностью и рамкой. Цвета принадлежат текущей теме Realize.
На mobile body занимает одну колонку с полем 16px без desktop-скругления;
навигация остаётся в общем drawer. Это общая компоновка всех потребителей shell.

Контентная сетка использует общий `--ui-layout-gap` из UiTheme (16px).
Видимые заголовки, поля и таблицы начинаются у левой границы workspace:
страницы не прибавляют собственные 28–34px к промежутку после sidebar.
Вертикальные секции, панели вкладок, строки карточек и колонки используют
тот же шаг. Настройки и каталог рабочих сред подчиняются этой же сетке.
Поля мобильной страницы задаёт shell, поэтому они не удваиваются потребителем.
Прокручиваемый main резервирует стабильный scrollbar gutter и внутреннее поле
справа `--ui-layout-gap` (16px): карточки и таблицы не касаются полосы прокрутки.

### Контекстная строка страницы

`breadcrumbs` выводятся внутри `main`, перед содержимым страницы. В той же строке
после пути располагается optional `backAction`: `onSelect`, контекстная подпись `label`
и optional `disabled`. Shell отвечает за компактную кнопку со стрелкой, accessible
name и видимый focus; направление перехода и защита несохранённых изменений
принадлежат host. Без крошек и backAction пустая строка не создаётся.
До следующего блока используется `--ui-layout-gap`; ширина строки ограничена
контентной колонкой. Touch-кнопка имеет цель 44px вместо desktop 30px.

В task reference кнопка ведёт к родительскому контейнеру по текущим крошкам:
список → папка → проект → рабочая среда, с учётом реально существующих уровней.
Из корня среды и настроек она открывает каталог сред, из каталога — текущие задачи.
Переходы проходят через существующий workspace manager и его dirty guard.
Прежняя отдельная кнопка возврата над заголовком настроек заменена общей строкой.
Это контекстный возврат; история браузера и task hash остаются у host.

`SystemAdminBreadcrumbs` принимает упорядоченные items с id, label, optional icon,
onSelect и optional choices/actions для переключения уровня и его настроек.
Меню каждого уровня показывает поиск, одноуровневые записи и текущий выбор.
Host вычисляет соседей по типу/родителю и ACL; shared component не читает store.
Без choices сохраняется обычный текст/переход. `currentAsHeading` превращает
последний уровень в h1, без повторного крупного заголовка ниже.
При длинном пути родительские уровни доступны через меню «Разделы пути».
На mobile при двух и более уровнях показываются это меню и текущий объект;
весь родительский путь остаётся доступен из меню, не вытесняя текущий пункт.
Уровни разделены небольшими точками по вертикальному центру. Контекстная строка
высотой36px не содержит вертикальной линии; кнопка30px следует за крошками.
На touch цель44px сохраняется. Иконки уточняют тип уровня, длинные названия
сокращаются с полным title; меню родителей сохраняет весь путь.
Тип контейнера выводится цветным UiBadge рядом с текущей крошкой-h1, без отдельной
строки. На узком экране его заменяет цветная иконка текущего типа; полное название
остаётся доступным в title и меню. `contentActions` shell размещает создание справа
от пути и back. Описание объекта остаётся в настройках, не дублируя строку пути.
UiBadge сохраняет tone для статуса и принимает optional accent из общей палитры
purple/blue/cyan/green/amber/rose. Палитра использует tokens текущей темы и
контрастный текст. Среда использует свой настроенный color, проект — blue,
папка — amber, список — cyan, архив — rose. Длинный h1 сокращается с title.
`UiEntityMark` выводит тематическую иконку либо переданное пользователем изображение,
с fallback при ошибке загрузки. В reference его данные и цвета определяет общий
taskLocationAppearance; одна и та же картинка видна в крошках, меню и дереве.

### Верхняя панель

У concrete Realize shell для фиксированного reference `toolbar` — optional slot
SystemAdminShell, а не обязательный API общего SDK. При его наличии он заменяет прежние
headerActions и отдельную кнопку темы. `SystemAdminToolbar` получает context,
searchEntries, createActions, notifications, onReadAll, user, profileActions,
optional billingActions, signOutAction, onCreate, onAssistant, theme/onThemeChange и locale/onLocaleChange.
Компонент не импортирует приложение.

Поиск открывается кнопкой или Ctrl/⌘K, принимает готовые доступные host entries,
фильтрует слова запроса по label/description/keywords, поддерживает стрелки/Enter,
пустое состояние, Escape и возврат focus. Shortcut не перехватывает другие модальные
окна. Данные поиска в reference: доступные активные среды, проекты, папки, списки,
задачи и действующие команды. Документы/файлы/люди добавятся с их источниками.

SystemAdminActionMenu переиспользует общий menu content/стрелку/стили и откладывает
callback до закрытия focus scope, чтобы создание и dirty guard получили focus.
Колокольчик имеет счётчик непрочитанного, список, отметку всех прочитанными и
пустое состояние. Данные и состояние чтения принадлежат host. В reference события
вычисляются из review/failed/blocked/pending-handoff задач текущей доступной среды;
чтение хранится только до перезагрузки. Исторический backend inbox не имитируется.

Переключатель среды переиспользует WorkspaceSwitcher в компактном topbar-варианте;
в боковой навигации второй переключатель не остаётся. Профиль показывает текущего
demo actor в identity-блоке. Далее идут личный кабинет и редактирование профиля,
отдельная группа баланса/пополнения, компактная строка настроек и выход последним.
Рабочие команды, архив и настройки среды принадлежат соответствующей навигации.
Тема переключается иконками солнца/луны с radio-семантикой; язык — иконкой глобуса
с раскрываемым выбором внутри меню; справка клавиш — иконкой. Tooltip, accessible names, выбранное
состояние и touch-цели44px сохраняются. Host передаёт profileActions, billingActions
и отдельный signOutAction; UI-kit не вызывает auth API.

В reference кабинет ведёт на действующий /account, профиль — /account#name,
выход — /logout (существующий users auth lifecycle). Переходы защищены host dirty
manager. Demo actor не выдаётся за authenticated user этих маршрутов. Старые
/accounts/* из quarantined _realize не используются. Баланса и платежного модуля
пока нет: оба пункта открывают явное состояние недоступности без выдуманной суммы,
формы оплаты или ложного успеха. Это ограничение host, а не общий visual contract.

Optional onCreate заменяет dropdown единой формой host; createActions остаются
контрактом доступных команд. В task reference окно содержит вкладки Задача,
Проект, Папка, Список и Рабочая среда. Это действующие сущности; тип задачи
выбирается в редакторе задачи. Основной ввод компактен; «Все поля задачи»
раскрывает дополнительные вкладки без сброса заполненных полей. Папка/список доступны и из корня среды:
форма предлагает разрешённый проект и родительскую папку. Черновик защищён при
закрытии и переключении типа. Новые формы не дублируют существующие commands.

Новый каркас поддерживает ru/en через собственные словари UI-kit; host хранит
выбор в `realize.system-admin.locale`, синхронизирует вкладки и начинает hydration
с русского server snapshot. Недоступный localStorage не блокирует переключение.
Язык передаётся явно, применяется к верхней панели, поиску, уведомлениям, профилю,
крошкам, меню выбора среды и заголовкам/вкладкам task reference. Имена и описания
объектов — данные пользователя, они не переводятся. Остальные доменные формы
reference пока русские; языковые маршруты storefront и Payload i18n независимы.
Кнопка ИИ открывает действующий `/admin/ai` через
host guard; встраивание его полноценного диалога справа остаётся следующим этапом.

### Целевой состав и дальнейшее расширение

Ниже описан целевой состав; фактически подключённые источники указаны выше.
Общие элементы передаются host; shell не получает зависимости от поиска,
аккаунтов, AI runtime или доменных коллекций.

- Переключатель текущей рабочей среды: один общий контекст приложения. При переносе
  в topbar заменяет существующий переключатель, не создавая второй источник выбора.
- Поиск и палитра команд с Ctrl/⌘K: задачи, проекты, документы, файлы, люди и действия,
  в рамках доступных пользователю данных; быстрый доступ к недавним результатам.
- Отдельная кнопка ИИ-ассистента: панель диалога справа с контекстом текущей страницы,
  новым диалогом, историей и переходом в полное представление.
- «Создать»: общие быстрые действия с учётом раздела и прав.
- Входящие: упоминания, назначения и запросы внимания с индикатором непрочитанного.
- Профиль: личные настройки, тема, язык, аккаунт и выход.

Desktop-порядок: среда → поиск/команды → создать → ИИ → входящие → профиль.
Поиск занимает гибкую центральную область; высота topbar и сетка остаются общими.
На узком экране приоритет имеют поиск, ИИ и профиль, остальные действия — в меню.
Активные фоновые операции и запросы подтверждения показываются по необходимости;
режим фокуса, справка и настройка панели могут находиться в меню профиля/панели.
Действия конкретной страницы остаются в её контенте.

Основания предложения: единая точка поиска и команд в
[ClickUp toolbar](https://help.clickup.com/hc/en-us/articles/11583054545303-Intro-to-the-toolbar)
и [JetBrains Search Everywhere](https://www.jetbrains.com/help/webstorm/searching-everywhere.html),
доступ к прежним диалогам через
[поиск ChatGPT](https://help.openai.com/en/articles/10056348-how-do-i-search-my-chat-history-in-chatgpt).

### Поведение глобальной навигации

Кнопка «Ещё» стоит после последнего раздела и тонкого разделителя внутри
прокручиваемого списка и открывает компактную панель со
скрытыми разделами в сетке и действием «Настроить навигацию». По умолчанию
Планер и Инструменты скрыты из основного списка, но доступны здесь. Мастерская
видна по умолчанию; ранее сохранённое пользователем скрытие не сбрасывается.
Активный скрытый раздел отмечается также на кнопке «Ещё». Выбор из сетки
включает раздел в основную панель с сохранением заданного порядка, сразу
убирает его из скрытых пунктов и открывает его полноразмерную панель.
Видимость сохраняется через общий preferences-контракт; Escape возвращает
фокус новой кнопке раздела. Повторно скрыть пункт можно в настройках.

Внизу desktop rail закреплена двойная стрелка «Раскрыть меню». Сегменты плавно
складываются в противоположную сторону при закреплении и обратно при
сворачивании, без вращения иконки. Общий SystemAdminDisclosureIcon использует
тот же переход для вертикальной стрелки переключателя среды; при
prefers-reduced-motion состояние меняется без анимации. Кнопка включает
постоянную панель: сохраняется уже открытый раздел, иначе показывается активный
раздел или доступный пункт каталога. В этом режиме уход курсора, клик снаружи,
прокрутка rail и выбор локального раздела не закрывают панель. Наведение или
фокус на пунктах меняет содержимое без повторного монтажа Dialog Content и
без загрузки страницы. Закрепление не меняет размеры и положение выбранного
вида панели: разделы имеют ширину280px и полную высоту rail, «Ещё» — компактную
ширину320px и высоту содержимого, настройки — ширину360px и полную высоту.
Новое содержимое начинается сверху. Повторный клик стрелки,
кнопка закрытия или Escape сворачивают панель и возвращают обычное hover-поведение.
Если host удаляет открытый раздел, закреплённая панель переключается на доступный.
Закрепление — локальное состояние текущей оболочки; preferences состава меню
не меняются. Mobile использует отдельный список разделов внутри drawer.

Настройка навигации позволяет включать и выключать пункты, менять порядок
перетаскиванием или кнопками вверх/вниз и восстанавливать значения по умолчанию.
При перетаскивании пользователь видит образ всей строки с названием и иконкой,
приглушённое исходное место и явный указатель вставки до или после конкретного
пункта. Подсказка называет перемещаемый раздел и место назначения. Hover не
сохраняет порядок: он меняется только при подтверждённом drop; отмена или
отпускание снаружи не меняют настройки. Анимация учитывает reduced motion.
Изменения применяются сразу; «Ещё» нельзя скрыть или переместить. UI-kit получает
`navigationPreferences` (`order`, `hidden`, optional `favorites`) и `onNavigationPreferencesChange`;
без них сохраняет настройки только на время жизни компонента. Host владеет
versioned localStorage, в reference настройки сохраняются в этом браузере и
синхронизируются между его вкладками. Это не настройка аккаунта или прав доступа.
Host registry задаёт `hiddenByDefault`; неизвестные сохранённые id игнорируются,
новые разрешённые разделы добавляются с настройками по умолчанию. Недоступное
хранилище не блокирует изменение меню в текущей сессии. Mobile использует те же
настройки без вложенного modal. Список показывает иконку, полное название и
стрелку перехода; выбранный раздел занимает отдельный экран с кнопкой
«К разделам». Кнопка закрытия drawer остаётся сверху. Список и содержимое
не выводятся одновременно. Прокручивается только список или body раздела;
хэдеры остаются на месте, учитываются safe-area и touch-контролы от44px.
Escape возвращает из раздела к списку, затем закрывает drawer; вложенное меню
действий первым обрабатывает Escape. Возврат восстанавливает фокус на разделе.

Hover открывает flyout справа с полным названием раздела и предоставленным host
содержимым. Компактный хэдер содержит иконку раздела, название, меню действий
и закрытие. Описание сохраняется в скрытом Dialog.Description для assistive
technology; видимой кнопки подсказки нет. Длинное название переносится целиком.
Escape закрывает панель; если открыто меню действий, сначала закрывается оно.
В desktop верх и низ flyout совпадают
с границами цветной панели навигации независимо от положения выбранной иконки
и объёма содержимого. Рамкой и её оформлением владеет сам SystemAdminNavigation;
Shell размещает его под логотипом. Стрелка остаётся напротив выбранной кнопки.
Resize окна или рамки пересчитывает положение и высоту открытого flyout.
Заголовок остаётся сверху, длинное содержимое прокручивается внутри body;
пустое место сохраняется при отсутствии подпунктов. Пока подпункты не заданы, показывается
явное пустое состояние. Известный маршрут или callback может быть отдельным
действием «Открыть раздел»; переход на несуществующую страницу не создаётся.
Наведение не меняет текущую рабочую область и active state раздела.

### Иерархия Задач в reference

Task manager передаёт собственное содержимое panel и secondaryNavigation из
одного доменного дерева: обзор, все задачи выбранного
Workspace, Project, Folder/Subfolder и List. Уровня Space нет. Панель показывает
один уровень без накопления отступов; вход в проект/папку и возврат сохраняют
панель открытой. Список и явный переход ко всем задачам контейнера меняют область данных. Счётчики вычисляются из общего store.
Создание контейнера получает явного родителя; архив ограничен текущим Workspace.

`panel` поддерживает ReactNode или функцию `(onNavigate) => ReactNode`, аналогично
secondaryNavigation. Callback закрывает обычный flyout/mobile drawer после выбора
location; закреплённая панель сохраняется. Custom panel не сопровождается вторым
действием «Открыть раздел». Дерево/формы/данные принадлежат task manager, UI-kit
сохраняет только общий shell/portal и примитивы. На mobile дерево доступно через
panel раздела «Задачи»; secondaryNavigation используется только на desktop.
Host передаёт мобильное содержимое в panel соответствующего раздела.
Незавершённые расширенные подпункты
из предложения по задачам не подменяют реально работающую иерархию.

### Подпункты Главной в reference

Home использует тот же grouped renderer с четырьмя группами:

| Группа           | Подпункты                  |
| ---------------- | -------------------------- |
| Рабочий стол     | Обзор; Мой день            |
| Требуют внимания | Входящие; Согласования     |
| Быстрый доступ   | Избранное; Недавние        |
| Рабочая среда    | Дашборды; Лента активности |

Host `systemAdminHome.navigation.tsx` задаёт состав и действия. Обзор ведёт
на существующий `/admin`; остальные будущие экраны представлены без href
и подписей «Планируется». Бейджи уведомлений не выводятся, в том числе
в избранном и быстрых ссылках.

Избранное — сохраняемый список выбранных пользователем пунктов меню. Кнопка
с горизонтальными тремя точками появляется при наведении на строку или фокусе
внутри неё; пока меню открыто, кнопка остаётся видимой. На touch-экране она
доступна постоянно. Зарезервированное место исключает скачки подписи.
Подсветка охватывает всю строку вместе с «…»: при наведении на любую её часть,
фокусе внутри строки и открытом меню действий. Выбранный пункт дерева задач
также получает общий фон и обводку строки; фокус клавиатуры остаётся у
отдельного контрола. Общий стиль UI-kit применяется через
`data-navigation-item="row"` и `data-navigation-item-select` к группам,
избранному, дереву и быстрым ссылкам задач. Заголовки панелей и переключатель
рабочей среды сохраняют собственное оформление.
Та же кнопка находится в заголовке раздела и у контейнеров/представлений задач.
Меню содержит применимые действия: «Добавить в избранное» или «Убрать из
избранного», затем «Открыть в новой вкладке» и «Копировать ссылку» при наличии
доступного адреса. Закрепление закрывает только меню и не выполняет переход. Первый Escape
закрывает меню действий, следующий — панель навигации. Фокус возвращается
к трём точкам, а после удаления строки — к сохранившейся области избранного.
Список «Главная → Избранное» показывает все закрепления в порядке добавления,
без демонстрационной подборки. Пустой список содержит инструкцию по добавлению.

Сохраняются только стабильные ID `section:<id>` и `link:<id>`, без URL, подписей
или callbacks. Актуальные значения и доступность берутся из текущего registry;
custom panels объявляют ссылки через optional `favoriteLinks` раздела. ID ссылок
уникальны в пределах каталога. `favoritesSlot` у строки обозначает место вывода
избранного и не добавляет сам контейнер в собственный список. В избранное
допускаются доступные рабочие ссылки с href/onSelect; `favoriteable: false`
исключает служебное назначение. Недоступные строки, пустые разделы и действия
настройки не закрепляются. Верхнеуровневые разделы требуют явного
`favoriteable: true`. В reference исключены обзор Главной, конфигурация
агентского слоя и архив задач; рабочие контейнеры, представления, ассистент
и запуски доступны. Старые закрепления вне разрешённого каталога удаляются
при нормализации preferences. Если у пункта нет доступных действий, «…» скрыто.
Закреплённый раздел открывает свою панель, подпункт выполняет существующее действие.
Скрытие раздела в rail не удаляет его из избранного; сброс видимости и сортировки
сохраняет закрепления. Удалённые из разрешённого каталога ID не отображаются.

Общий контекст shell обслуживает desktop, mobile и дополнительную навигацию;
публичный `SystemAdminItemMenu` позволяет custom panel использовать тот же
контракт. Host хранит optional `favorites` в прежнем version 1 envelope localStorage.
Старые настройки без этого поля остаются валидны; повреждение favorites не сбрасывает
порядок/видимость. Reference сохраняет выбор в этом браузере, синхронизируя вкладки;
серверное хранение по аккаунту относится к последующему внедрению.

Видимого заголовка у меню нет; название пункта сохраняется в aria-label.
Вытянутый указатель 20×12 принадлежит общему SystemAdminPopoverArrow у панели навигации,
ItemMenu и переключателя среды, без обводки основания и без наложения на
закруглённый угол. Radix позиционирует её при flip. Меню плавно появляется и
закрывается от точки привязки; reduced-motion отключает переход.
SystemAdminMenuContent объединяет анимацию и указатель. Клик по собственному
переключателю обрабатывается только им: закрывающийся слой меню не отменяет
повторное открытие во время анимации выхода.
Действия со ссылкой не зависят от возможности закрепления. Общий ItemMenu
принимает optional href; используются только http(s) адреса. Новая вкладка —
нативная ссылка с target=_blank и rel=noopener noreferrer. Копирование передаёт
абсолютный адрес в Clipboard API и показывает результат в открытом меню,
включая отказ браузера; текущая страница остаётся на месте. У callback-only
пунктов без собственного URL эти действия не предлагаются. Недоступные строки
не передают адрес в меню; запрет закрепления служебного пункта сохраняется.
Меню использует Radix Dropdown Menu в non-modal режиме с позиционированием
и обработкой границ viewport. Его DOM остаётся внутри текущей панели, чтобы
сохранить тему, проверку outside click и мобильный focus trap. Внешняя панель
не обрабатывает Escape, пока открыто дочернее меню.

Строка UI-kit допускает optional `shortcuts` с тем же контрактом ссылок.
Вложенный список визуально отступает от родительского пункта; disabled родителя
не запрещает самостоятельные доступные shortcuts. Каждая строка проверяет
свои href/callback/disabled и использует тот же onNavigate. Доменные данные и
выбор доступных объектов не переходят в UI-kit.

Optional `footerAction` размещает действие под прокручиваемым body. Для Home
это «Настроить рабочий стол», пока disabled: экран настройки ещё не создан.
Footer остаётся доступен при desktop scroll; mobile сохраняет естественную
прокрутку drawer. Оформление использует общий secondary UiButton с
disabledAppearance=preserved: фон, контраст, тень, высота и иконка17px совпадают
с «Настроить навигацию», ширина заполняет соответствующую панель.
Нативный disabled сохраняется; новый экран
Главной, персонализация виджетов и серверная логика этим этапом не реализуются.

UI-kit принимает необязательные `groups` в `SystemAdminNavigationItem`.
Группа содержит `id`, `label` и массив `items`; строка — `id`, `label`, `icon`,
необязательные `description`, `href`, `onSelect`, `disabled`, `statusLabel`.
Disabled имеет приоритет над href/callback; отсутствие обоих действий также
делает строку недоступной. Заголовки групп не кликабельны. Список прокручивается
в существующем flyout body и не создаёт вложенный Dialog или второй scroller.
Существующий `panel` имеет приоритет над группами, сохраняя контракт custom content.
Выбор доступного пункта использует общий onNavigate; закрепление сохраняется,
обычное hover-меню и mobile drawer закрываются. Группы заменяют пустое состояние;
при их наличии общий «Открыть раздел» не дублирует действия подпунктов.

Первая группа не выводит видимый заголовок и разделитель, сохраняя доступное
имя группы. У последующих групп тонкая линия продолжается справа от заголовка
по центру строки. Полосы прокрутки навигационных панелей тонкие, с прозрачной
дорожкой. Кнопки настройки навигации, рабочего стола и аналогичные действия
подвала используют size=small. Справа от пункта доступно меню действий «…». Контракт строки
не содержит счётчиков уведомлений; описания сохраняют доступность для
assistive technology. Количество задач в дереве раздела «Задачи» принадлежит
task manager и сохраняется как информация о содержимом контейнера.

Профили, роли, навыки, правила, шаблоны, процессы, возможности, проверки,
версии конфигурации и системная основа сохраняют владельца в агентском слое.
Задачи принадлежат task manager, подключения провайдеров — интеграциям.
Новые каталоги будущего раздела AI не дублируют эти источники данных.

Переход курсора с trigger в flyout не закрывает меню; небольшая задержка
закрытия позволяет пересечь зазор. Click/Enter/Space открывают тот же flyout,
Escape закрывает его и возвращает focus, outside dismiss и Arrow navigation
доступны с клавиатуры. Touch использует нажатие. Flyout ограничен viewport,
не обрезается прокруткой rail и не перехватывает focus при обычном hover.
Mobile сохраняет общую структуру разделов внутри доступной navigation drawer:
именованный список разделов и отдельный экран содержимого выбранного раздела. Вложенный modal
не создаётся; Escape сначала закрывает панель раздела, затем сам drawer.

Shell ограничивает переполнение через `overflow: clip` и не прокручивается при
автоматическом переносе фокуса. Рабочий контент имеет собственный containing
block и прокрутку; абсолютные вспомогательные элементы не увеличивают страницу.

## Host adapter и маршруты

`src/app/(system-admin)/layout.tsx` — самостоятельный Next root layout с Geist,
без `@payloadcms/next/css`, Payload RootLayout или DefaultTemplate.
`/system/task-manager/reference` проверяет сессию через серверный Payload API и
роль admin, затем открывает client reference. Client получает только безопасные
props. `/system/task-manager` использует тот же gate и shell с постоянными
данными `@realize/payload-task-manager`; его client context содержит только
`initialTheme`, `themeCookieName` и `currentActor: { id, name }`, без email, token
и Payload document. Имя theme cookie задаётся host как `${cookiePrefix}-theme`.
`useSystemAdminTheme` сохраняет выбранный режим рабочего Task Manager в эту
существующую cookie на год; сервер восстанавливает выбор после reload и перехода
между защищёнными страницами. UI-kit получает mode/callback и не владеет cookies.
Доступ к данным дополнительно проверяется task domain на каждом запросе.
`src/components/admin/system-shell/` адаптирует host context/авторизацию.
`requireSystemAdmin` считывает request headers до инициализации Payload:
Next определяет зависимость защищённого экрана от запроса до подключения к БД.
Это позволяет штатной production-сборке без DB credentials пропустить
prerender защищённых страниц; сессия и роль проверяются при реальном запросе.
Центр `/system/access` и подтверждение CLI `/system/access/device` используют
тот же template host с режимом `cookieOnly`: непустая Users cookie, отключённый
autoLogin, проверенная `local-jwt` strategy и отсутствие Authorization header.
Оба точных management route доступны также при native shell policy; остальные
рабочие маршруты сохраняют прежний guard. Native entry и раздел настроек ведут
в центр доступов, карточка Users — на owner-фильтр. Lifecycle, scopes и
одноразовая выдача секрета определены в [контракте доступов](platform-access.md).
`/reference/task-manager` остаётся публичной демонстрацией вымышленных данных.

Admin entry отдельно показывает «Референс задач» (`/system/task-manager/reference`)
и «Рабочий Task Manager» (`/system/task-manager`), сохраняя доступ к эталону
при появлении постоянного хранилища. Ссылка рабочего экрана не считается
выбранной на вложенном reference URL. Прежний
`/admin/task-manager/reference` сохраняется как явный redirect к защищённому
эталону, без собственного renderer/fixtures. Владелец URL — тонкий Next route;
единственный UI owner находится на `/system/task-manager/reference`.
Существующие `/admin` экраны и сессии сохраняют своих владельцев.

Отделение CSS и разметки защищает новый UI от визуальных изменений Payload.
Контракт авторизации/данных всё ещё зависит от Payload; обновления требуют
совместимости adapter и проверок доступа. Полную независимость приложения
от Payload этот шаблон не обещает.

## Постепенная миграция

1. Task manager reference использует общий шаблон в обоих hosts.
2. Следующий выбранный экран переносится целиком вместе с data adapter и
   browser evidence; старый UI owner удаляется после перевода consumers.
3. AI assistant, Media и integrations переносятся отдельными задачами;
   их существующие providers, permissions и события не заменяются заглушками.
4. Нативные редакторы Payload остаются доступными до отдельных решений по ним.

Миграция не вводит новые auth cookies, обход ACL, дублирующую БД или fork Payload.
Shell поставляется самостоятельным workspace package Realize. Универсальный
installer и выпуск из Мастерской развиваются по одному lifecycle в
[спецификации расширений](../specifications/extension-management.md).

## Приёмка

Одинаковые размеры, темы и hover/focus у публичного и системного host;
отсутствие двойной шапки/навигации; доступная мобильная навигация и portal;
проверка redirect без сессии/admin и отсутствие Payload stylesheet в document.
Проверяются конкретные обновлённые потребители UI-kit, а не весь Admin по
предположению. Скриншоты и результаты runtime сохраняются у задачи.

## Единообразие групп и навигация задач

SystemAdminNavigationSection владеет общим заголовком группы, линией-разделителем
и местом компактного действия. Первой группе видимый заголовок не нужен.
Tasks использует тот же renderer и общие строки быстрых переходов; workspace
является контекстом, затем следуют переходы, проекты/содержимое и архив.
Смена Workspace сохраняет панель открытой для последующего выбора проекта.
Host может передать `active` общей строке: текущий переход получает aria-current
и выделение, сохраняя выбор «Все задачи» и «Архив» при общем renderer.
На desktop правая граница scroll container совпадает с наружным краем flyout:
однопиксельная рамка не создаёт отступ для scrollbar. Mobile не получает
компенсации у inline flyout; внешняя рамка drawer нарисована внутренней тенью,
чтобы не отнимать ширину у прокрутки. Создание работает в выбранном контексте,
без inline-набора мелких кнопок на каждом уровне дерева.

## Управление рабочими средами

Task reference передаёт в общий shell каталог и настройки сред как собственные
экраны. Быстрый переключатель показывает доступные активные среды, поиск и
команды каталога/создания. Вход в «Рабочие среды» всегда доступен из Tasks.
Настройки общей среды не смешиваются с персональными preferences навигации.
UI-kit остаётся независимым от Workspace и не хранит модель/права task manager.

Переключатель показывает название первым, ниже — подпись «Рабочая среда».
Высота 40px на desktop и не менее 44px на touch. Переключатель и отдельная кнопка
настроек имеют общий hover/open фон при сохранении самостоятельного focus.
Выпадающее меню ограничивает область списка пятью строками и выдаёт по десять
сред; «Показать ещё» добавляет следующую порцию, сохраняя меню открытым и переводя
фокус к первой добавленной среде. При закрытии/новом поиске лимит сбрасывается.
Поиск фильтрует весь доступный активный каталог; команды и поиск не прокручиваются
вместе со списком. Тонкий scrollbar списка использует общий контракт
UiTheme через data-navigation-scroll. UiSearchInput в существующем input owner задаёт общий мягкий
фон, иконку поиска и focus для переключателя, проектов и каталога сред.

## Действия над контейнерами задач

Блок «Проекты» меняет заголовок на «Разделы» внутри проекта/папки. Постоянная
строка контекста содержит название и возврат, поэтому поиск не сдвигается при
входе внутрь. Нажатие названия строки открывает задачи контейнера; отдельная
стрелка просматривает вложенную структуру без закрытия панели.
Одна кнопка «+» открывает создание в текущем контексте и переключатель
«Показать скрытые». Меню «…» предлагает открытие, настройки, скрытие/возврат
в навигацию, избранное и удаление с подтверждением.

SystemAdminItemMenu принимает optional actions и настраиваемый trigger;
геометрия, focus, анимация и опасные действия остаются общими для всех меню.
При открытии диалога из меню возврат фокуса не должен перехватывать его focus.
Указатель — вытянутый треугольник с обводкой только боковых сторон.

Optional hiddenItems в прежнем version1 envelope хранит персональную видимость
контейнеров через стабильные link ID. Нормализация разделов сохраняет это поле;
права и задачи не меняются. Скрытые строки доступны через «Показать скрытые».
Удаление ветки очищает её favorites/hiddenItems. Настройки и удаление принадлежат
локальному task store и проверяют доступ рабочей среды; UI-kit не знает TaskLocation.

Подтверждение удаления использует общий UiConfirmation: компактная карточка
с названием и ненулевыми счётчиками содержимого вместо большого окна формы.
При блокировке показана короткая причина и «Понятно». Карточка не исчезает по
таймеру, принимает явное решение и сохраняет клавиатурный focus/возврат,
включая открытие из мобильной навигации.
После удаления исходной строки task manager возвращает фокус в обновлённый
список навигации через общий onCloseAutoFocus; отмена возвращает его кнопке строки.
