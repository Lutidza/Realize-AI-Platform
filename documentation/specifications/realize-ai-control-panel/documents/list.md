# Список документов в RealizeAI Control Panel

<a id="implemented-document-list"></a>

## Действующий список, пагинация и переходы

**Реализовано и проверено в изолированной среде 2026-11-22.** Список
`/system/documents` и чтение `/system/documents/[slug]` образуют раздел
в `panel-content` Control Panel.
Экран `DocumentListScreen` показывает заголовок «Документы» и одну поверхность
со списком. В строке есть ссылка-заголовок, краткое описание при наличии и дата
обновления. На мобильном поля идут друг под другом. Для пустой коллекции
показывается «Документов пока нет». Экран использует `UiContainer` и `UiSurface`.
Переходы принадлежат разделу и доступны в обоих макетах через `panel-content`.
Общие границы контейнера, отступы и результаты измерений описаны в
[сетке экранов документов](../shell/content-grid.md#document-screen-geometry).

Пункт «Документация» в меню системной оболочки открывает `/system/documents`.
В штатном Payload запись коллекции «Документы» находится в группе `Content`
и ведёт на `/admin/collections/documents` для администратора.

### Серверная выборка

Сервер проверяет административную сессию и читает список от имени пользователя.
Условия запроса к Payload и проверки доступа приведены в
[контракте коллекции](collection-and-access.md#document-list-access).
На страницу загружается до 20 записей с сортировкой `-updatedAt`, затем `-id`.
Серверное представление записи содержит только `slug`, `title`, необязательное
`description` и ISO `updatedAt`. Экран получает эти поля и метаданные
пагинации. Текст и разделы загружаются при открытии документа.
[Контракт защищённого чтения](reading.md#protected-document-reading).

### Адреса и возврат к списку

| Маршрут | Параметр | Семантика |
| --- | --- | --- |
| `/system/documents` | `page` | Номер страницы списка. Без параметра открывается первая страница. |
| `/system/documents/actions/create` | `fromPage` | Действие «Создать статью» рядом с заголовком открывает форму с номером текущей страницы. [Контракт формы](creation.md#document-article-creation). |
| `/system/documents/[slug]` | `fromPage` | Страница для ссылки «Все документы» над статьёй. Без параметра ссылка ведёт на первую страницу. |

`page` и `fromPage` принимают одно положительное целое десятичное значение
в поддерживаемом диапазоне. Некорректные или повторяющиеся значения дают 404.
Канонические ссылки опускают значение `1`. После проверки доступа запрос
страницы за концом списка перенаправляется на последнюю доступную страницу
или на первую при пустой коллекции. Ссылки пагинации, перехода к чтению и
возврата сохраняют текущие `mode` и `layout` в `href`, включая изменения через
панель предпросмотра. Отсутствие `layout` означает наследование макета по
умолчанию. Возврат использует фиксированный маршрут списка и проверенный
номер страницы. При смене страницы списка прокручиваемая область содержимого
открывается сверху.

`DocumentListScreen` зарегистрирован как компонент проекта
`realize/document-list-screen@0.1.0`. Server binding связывает его с существующим
project owner и renderer. Agent metadata имеет режим `descriptive-only`, editor
metadata — `metadata-only`.

### Проверки и поставка

На отдельном PostgreSQL применены 35 миграций и через Payload API сохранены 22
тестовых документа. Проверены пустой список, разбиение 20 + 2, порядок при
совпадающих датах, восемь некорректных URL и три канонических перенаправления.

В Chromium на 1440 × 900 и 390 × 844 проверены `default` и `without-topbar`.
Сценарий покрывает смену страницы, макета и темы, чтение сохранённого
документа, возврат на страницу 2 и переход на страницу 1. Проверены открытие
фактического `href` в новой вкладке и возврат по прямой ссылке на чтение с
наследуемым макетом. Временная БД и процессы остановлены после приёмки.

## Согласованный целевой контракт

**Согласовано 2026-11-24.** Список документов станет первым потребителем
[общего списка записей на базе Ant Design Table](../../components/record-list/INDEX.md#record-list-contract).
Модуль документов объявляет доступные поля, действия и возможности запроса.
Сервер проверяет права, ищет по `title` и `slug` и применяет разрешённую
сортировку до пагинации по всей доступной коллекции. Скрытый `slug` участвует
в поиске.

| Столбец | Исходный вид | Поведение |
| --- | --- | --- |
| `title` · Название статьи | Видим всегда, по умолчанию первый. На десктопе допускает перестановку и изменение ширины, на мобильном остаётся первым в записи. | Текст из `title`, обычная ссылка на чтение по `slug` с фокусом и открытием в новой вкладке. Нажатие на заголовок столбца меняет серверную сортировку по названию. Длинное название переносится по словам. |
| `updatedAt` · Обновлено | Виден, можно скрыть. Исходная сортировка по убыванию времени. | Ячейка показывает дату в действующем формате `ru-RU`, UTC. Сортировка использует исходную временную метку и устойчивый дополнительный ключ `id`. При скрытии столбца порядок сохраняется и виден в панели списка. |
| `slug` · Адрес статьи | Скрыт, доступен в настройках колонок. | Ячейка показывает короткий адрес и действие «Скопировать ссылку на статью». Копируется абсолютный адрес защищённого экрана на текущем домене, без `fromPage`, `mode`, `layout` и параметров выдачи. Переход по названию сохраняет контекст возврата в список. |

В обоих макетах сохраняются `fluid` и внешний радиус как у sidebar.
При ширине 1024 px и меньше под названием выводятся выбранные дополнительные
поля с подписями. Администратор задаёт вид раздела, пользователь может
вернуться к нему из своего персонального вида. Общие правила определены
в [контракте столбца](../../components/record-list/columns.md) и
[настройках представления](../../components/record-list/views.md).

## Предложение к согласованию · привязки и примеры документов

Примеры применяют предложенные типы
[общего компонента](../../components/record-list/INDEX.md#record-list-contract-proposal).
Преобразование определения столбцов в свойства таблицы описано в
[адаптере Ant Design Table](../../components/record-list/ant-table.md).

**Привязки документов.** Предлагаемые `listId` и `viewId` — `documents` и
`default` в экране `realize/document-list-screen`. Пример использует три
согласованных столбца. Существующее необязательное `description` можно позднее
добавить скрытым текстовым столбцом. Для `rowKeyField: "id"` и `pagination.total`
потребуется дополнить текущую проекцию стабильным ID записи и точным
количеством доступных записей после поиска и фильтрации.

Настройки представления документов действуют в обоих макетах панели. При
возврате из статьи раздел восстанавливает проверенные параметры запроса
и текущие `mode` и `layout`.

```ts
type ArticleColumn = "title" | "updatedAt" | "slug";
const documentsList: ListDefinition<ArticleColumn, ArticleColumn | "id"> = {
  schemaVersion: "1.0",
  rowKeyField: "id",
  searchFields: ["title", "slug"],
  columns: [
    { id: "title", field: "title", label: "Название статьи", role: "primary",
      cell: { kind: "link", actionId: "openArticle" }, sortable: true },
    { id: "updatedAt", field: "updatedAt", label: "Обновлено", role: "secondary",
      cell: { kind: "date", formatId: "documentUpdatedDate" }, sortable: true },
    { id: "slug", field: "slug", label: "Адрес статьи", role: "secondary",
      cell: { kind: "text", copyActionId: "copyArticleLink" }, sortable: false },
  ],
  defaults: {
    columns: { slug: { visible: false } },
    defaultSort: { columnId: "updatedAt", direction: "desc" },
  },
};
```

**Пример персональной настройки.** Пользователь включает адрес и перемещает
его вслед за названием. Подписи, ширины и видимость даты наследуются от раздела.

```json
{
  "schemaVersion": "1.0",
  "key": {
    "screen": { "namespace": "realize", "id": "document-list-screen" },
    "listId": "documents",
    "viewId": "default"
  },
  "settings": {
    "order": ["title", "slug", "updatedAt"],
    "columns": { "slug": { "visible": true } }
  }
}
```
