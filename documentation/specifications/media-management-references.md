## 2. Аннотации и границы заимствования

**Payload.** Сохраняем встроенную форму, обработку ошибок и upload-поля.
В установленном Payload 3.88 focal point включается через `imageSizes`,
`resizeOptions` или явное `upload.focalPoint: true`; папки включаются отдельно
и означают связи между документами. Публичный `EditUpload` позволяет получить
crop/focal через `onSave`, а применение этих параметров остаётся ответственностью
интеграции. Наличие native crop не доказывает сохранение
неизменяемого оригинала: это требуется отдельно подтвердить в нашей интеграции.

**Sanity.** Главное — контекст выбранного материала и удобное переключение между
поиском и деталями. На мобильном такая композиция становится последовательными
экранами. Не переносить чужую модель аккаунтов, тарифов, ролей или автоматизаций.
Защиту связанного файла от удаления реализовать по нашим действительным связям.

**Cloudinary Library.** Применить сетку/список и быстрый preview. Mosaic —
необязательное усложнение: для V1 достаточно предсказуемой сетки с равными
контейнерами. Technical IDs, все DAM-вкладки и редакторы продукта в наш основной
поток не переносить.

**Cloudinary Upload.** Использовать как референс состояний и управления фокусом,
а не как обязательный внешний uploader. Поставщик отдельно оговаривает отсутствие
keyboard cropping; это ограничение нельзя выдавать за достаточную доступность
нашего кадрирования. Проверяем свой интерфейс и даём альтернативу drag-and-drop.

**Shopify.** Использовать практичные фильтры и явные столбцы. «Используется»
должно означать проверенные ссылки нашего контента, включая черновики и версии.
Не переносить чужие числовые лимиты загрузки и поведение смены URL при переименовании.

## 3. Карта интерактивного макета

Все семь разделов образуют одно рабочее пространство с заметной подписью
«Макет интерфейса. Демонстрационные данные». Широкий экран: навигация около
200–220 px, гибкая область материалов, открываемые детали около 300–340 px.
Это ориентиры вёрстки, а не фиксированные ограничения ширины. На мобильном
поиск, результаты и детали открываются последовательно, без трёх узких колонок.

| Раздел                   | Композиция и локальные действия                                                                                     | Обязательные примеры и границы                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Библиотека — Library     | Поиск, фильтры по типу/назначению, сетка/список, выбор, счётчик и открытие деталей                                  | Наполненная библиотека, длинное имя, пустой результат, выбранные файлы; папки — пример будущей native навигации                   |
| Добавление — Upload      | Явная кнопка выбора, дополнительный drag-and-drop, строки выбранных файлов, назначение, удаление локального примера | Выбор файла добавляет его только в макет; ошибки и очередь демонстрационные, реальная передача и процент обработки не имитируются |
| Детали — Details         | Превью, метаданные, alt/подпись; вкладки «Сведения / Варианты / Использование», закрытие и возврат к библиотеке     | Фото, прозрачная графика, маленькое изображение, отсутствующий alt; варианты и связи — примеры, сохранения Media нет              |
| Профили — Profiles       | «Фото товара», «Баннер», «Контент»; таблица small/medium/large, размеры, формат, качество и сводка                  | Можно редактировать пример в текущем сеансе; это не сохранённая или активированная версия рабочего рецепта                        |
| Обработка — Processing   | Сводка партий, строки «Ожидает / Готово / Ошибка», объяснение отказа, демонстрация повтора                          | Явно обозначенные состояния примера; нет запуска Jobs и фиктивного отчёта об обработке                                            |
| Выбор для блока — Picker | Пустое/выбранное изображение, общая библиотека, подтверждение/отмена, локальные alt и подпись                       | Те же карточки и поиск, возврат фокуса при закрытии; рабочие страницы и upload-поля не изменяются                                 |
| Источники — Sources      | Несколько прямых официальных ссылок, что взято из каждого образца и что сохранено из Realize                        | Источники доступны для review; чужие сервисы, загрузчики и облачные интеграции не подключаются                                    |

Примеры используют семь URL существующих изображений проекта; локально
выбранные файлы не отправляются на сервер. Диагностика собственного локального
файла подтвердила освобождение его object URL при уходе из макета.
Смена вкладки или фильтра не выдаётся за
сохранение. При необходимости реальной загрузки пользователь переходит в
штатную Media: list/create, Bulk Upload, редактор и selector сохраняют своих
владельцев, права и обработку ошибок.

Рабочая область компонентов — `src/components/admin/media/reference/`.
Host зарегистрировал отдельное collection view у `src/collections/Media.ts`:
`/admin/collections/media/reference`; перед штатным списком добавлен вход
«Посмотреть макеты». Встроенная оболочка Payload сохраняется;
макет не создаёт второй admin layout, uploader, folder API или persistence.
Модальный выбор размещён порталом в `document.body` с собственной обёрткой
`UiTheme`, чтобы оформление и слой модального окна сохранялись вне контейнера
страницы. Это размещение проверено в финальной браузерной приёмке макета.

## 5. Приёмка текущего среза

Для завершения этапа проверяются следующие условия.

1. Доступны семь согласованных разделов и понятная граница демонстрационных
   данных. Наполненная библиотека, длинное имя и пустой поиск доступны для review.
2. Поиск, фильтры, сетка/список, детали и выбор для блока используют общее
   состояние; подтверждение/отмена и возврат фокуса ведут к ожидаемому экрану.
3. Локальный файл появляется только в макете и удаляется из него; серверных
   upload/write запросов нет, object URLs очищаются. Ошибка или повтор обработки
   явно относятся к примеру, не к рабочим Media/Jobs.
4. Примеры профилей и использования помогают оценить будущий сценарий, но
   не показывают фиктивное сохранение, активацию или проверку связей. Штатные
   Media list/create/selector остаются доступными без подмены их поведения.
5. Desktop и узкий экран, светлая/тёмная темы, keyboard, Escape/возврат фокуса,
   длинное содержимое, последняя кнопка и отсутствие горизонтального overflow
   подтверждены браузером на фактической вёрстке после интеграции.
6. Итог содержит адрес просмотра, точные пути снимков, результаты действий и
   непроверенные части. Исследование или успешный TypeScript не заменяют готовый
   экран.

На интегрированном макете подтверждены семь разделов, поиск/фильтры и
пагинация, сохранение контекста страницы, открытие/закрытие деталей и возврат
фокуса, выбор/удаление локальных файлов, подтверждение/отмена выбора для блока.
Светлая и тёмная темы проверены на 320, 390, 1024 и 1440 px; после исправления
плотности и breadcrumb горизонтального overflow нет. В browser evidence
зафиксировано ноль записей Media/Pages и ноль серверных загрузок.

## 6. Агентский процесс и передача реализации

Три текстовых шага исследуют источники, предлагают композицию и готовят

Обязательные проверки Code Lane — `secrets`, `lint`, `typecheck`, `test:int`,
`build`; их назначает сервер, а выполняет orchestrator. Придуманный npm script,
незарегистрированный существующий script или адресная команда не заменяют
этот набор. Браузерная приёмка макета после host-интеграции остаётся отдельной
необходимой проверкой отображения и действий.
