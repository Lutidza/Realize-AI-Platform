# Заключение независимого ревьюера и приёмка аудита статьи

**Согласовано и проверено в изолированной PostgreSQL, 2026-11-25.** Срез относится к аудиту формы «Создать статью». Входом служат опубликованные отчёт и карта покрытия, уже полученные независимым ревьюером по своему назначению. Результатом служит версия заключения в досье и отдельное решение оркестратора по этому аудиту. [Предшествующий этап](article-audit-publication.md) · [Модель исполнения и досье](attempts-and-dossier.md)

## Что именно проверяет ревьюер

Ревьюер сверяет четыре критерия с закреплёнными версиями исходников и правилами назначения.

| Критерий | Что должно быть видно в отчёте |
| --- | --- |
| Карта обязанностей | Для каждого из 12 файлов указана роль или обоснован пропуск. Можно найти JSX, стили, состояние, типы и валидацию. |
| Создание | Прослеживается переход от маршрута и формы через состояние и server action до проверки доступа, валидации и записи. |
| Проверка результата записи | Видно, как после неопределённого исхода находятся и сравниваются сохранённая статья и отправленный черновик. |
| Замечания и пределы проверки | У каждого выявленного нарушения есть правило, путь, строки и влияние. Указано, какие утверждения подтверждает статическое чтение и для каких нужен браузер или БД. |

Каждая оценка содержит идентификатор критерия, вывод с обоснованием, точную цитату проверяемого отчёта и ссылки на собственные квитанции ревьюера. Квитанция указывает попытку, версию исходника и выданные строки. Сервер сопоставляет диапазон с картой аудитора. Для подтверждающих предметных ссылок требуется покрытие аудитором. При расхождении ревьюер указывает конкретное исправление и способ его проверки. Его чтения сохраняются отдельно от карты аудитора. Смысл цитаты и достаточность доказательств оценивает специалист. [Критерии исходного назначения](../../../../.ai/templates/worker-assignment/TEMPLATE-WORKER-ASSIGNMENT-MANIFEST.md#приёмка-аудита-формы)

## Публикация и доставка

1. Runtime удостоверяет уже выданную попытку ревью и участника. Task Manager сверяет действующее назначение, независимость, доступ, проект, задачу, исполнение, итерацию, версии отчёта и карты. Отдельное основание приёмки закрепляет получателя, ревизию и отпечатки критериев и политики. До выдачи предметных строк сервер закрепляет это основание за попыткой. При каждом чтении и публикации сверяются исходное и действующее основания. Новая редакция критериев требует новой попытки.
2. В одной транзакции досье сохраняет неизменяемый результат с вердиктом `confirmed` либо `needs_changes` и событие доставки. Одно место результата принадлежит одной попытке. Совпадающий повтор возвращает сохранённую версию. Противоречащий повтор даёт конфликт.
3. Диспетчер доставляет ссылку во входящие уполномоченного оркестратора. Получение материалов требует действующего доступа. После сбоя между публикацией и доставкой диспетчер восстанавливает работу по сохранённому событию. Повтор доставки сохраняет единственную запись.
4. Отзыв прав, замена плана, несовпадение текущего основания или недоступные материалы останавливают зависимую операцию. Технический отказ сам по себе не является замечанием к аудиту. До устранения препятствия сохраняются существующие версии и решения.

## Решение и получатель доработки

| Действие оркестратора | Предпосылка | Что сохраняется |
| --- | --- | --- |
| Принять аудит | Заключение подтверждает четыре критерия. Выявленное и верно описанное нарушение в коде совместимо с приёмкой качества аудита. | Решение, автор, причина, ссылки на точные версии и основание. |
| Вернуть аудитору | Указаны расхождения в отчёте и критерии повторной проверки. | Решение и адресованная работа по исходному назначению аудитора с указанием ожидаемой итерации. |
| Запросить уточнение у ревьюера | Для решения нужно уточнить обоснование конкретного критерия. | Решение и адресованная работа по назначению ревьюера. |

Решение и адресованная работа фиксируются атомарно. Перед записью повторно проверяются участник, доступ и версии основания и заключения. Совпадающий повтор возвращает прежнее решение. Из конкурирующих различных решений сохраняется одно. Версии отчёта, карты и заключения остаются доступны по правилам досье. После возврата исполнитель получает поручение из входящих. [Доработка и повторная приёмка](article-audit-rework.md). Закрытие всей задачи определяется её политикой.

## Воспроизведение

Команда `npm run ai:assignment:conclusion-pilot` поднимает отдельный временный кластер PostgreSQL. Контракт проверяется детерминированными участниками. Границей этого среза служит сохранённое решение и, для доработки, доступная адресату запись. [Инструмент и порядок запуска](../../../../.ai/tools/worker-assignment/README.md#заключение-ревьюера-и-приёмка)


В проверке имитатор аудитора прочитал 13 диапазонов в 12 файлах формы. Независимый имитатор получил собственные квитанции. В первом отчёте описано сравнение найденной статьи с отправленным черновиком. Во втором утверждается, что достаточно найти запись по slug. Расхождение по критерию `verification-chain` приводит к поручению исходному аудитору.

| Проверка на PostgreSQL | Наблюдаемый результат |
| --- | --- |
| Аварийное завершение издателя после commit и повторная доставка | Новый процесс доставляет сохранённое заключение один раз. Конкурирующие разные решения оставляют один результат. |
| Ошибка записи события или поручения внутри транзакции | Половина операции не сохраняется. После устранения сбоя повтор завершается успешно. |
| Подмена цитаты, пути, хеша, квитанции, диапазона или ссылки на ревизию | Зависимая операция отклонена. Независимые чтения не расширяют карту покрытия аудитора. |
| Смена критериев или политики до публикации либо решения | Исходная попытка сохраняет прежнее основание. Устаревшее заключение исчезает из ожидающих решения. |
| Отзыв явного разрешения либо членства Foundation | Выдача и запись проверяют текущие полномочия. Сохранённые результаты доступны участникам, сохранившим права. |
