# Заключение независимого ревьюера и приёмка отчёта аудитора

**Статус.** Контракт согласован. Первую реализацию проверили на изолированной PostgreSQL 2026-11-25. Независимый ревьюер получает по своему назначению опубликованные версии отчёта и карты покрытия. Он публикует заключение в досье задачи. Уполномоченный оркестратор фиксирует отдельное решение по этой версии заключения. [Публикация отчёта и карты](audit-report-publication.md) · [Модель исполнения и досье](attempts-and-dossier.md)

## Что именно проверяет ревьюер

Заключение версии 1 (`schemaVersion: 1`) содержит резюме в `summary`, рекомендацию в `recommendation` и по одной оценке в `assessments` на каждый критерий. Валидатор принимает четыре идентификатора из `REVIEW_CRITERIA`. Предмет проверки и файлы берутся из проверяемого назначения. Хеш критериев закрепляет основание проверки, а допустимые идентификаторы задаёт код. [Формат заключения](../../../../packages/payload-task-manager/src/server/audit-review/conclusions/ReviewConclusion.types.ts) · [Перечень критериев](../../../../packages/payload-task-manager/src/server/audit-review/conclusions/reviewCriteria.constants.ts)

| Идентификатор | Что проверяет ревьюер |
| --- | --- |
| `responsibilities` | Отчёт объясняет роль каждого файла в области назначения или причину пропуска. Заявленное покрытие согласуется с фактическими чтениями. |
| `create-chain` | По доказательствам в отчёте можно проследить проверяемую операцию от входа до её результата, включая применимые проверки доступа и валидацию. |
| `verification-chain` | Отчёт показывает, как устанавливают фактический результат операции и сверяют его с ожидаемым, в том числе при неопределённом исходе. |
| `findings-and-limits` | Для каждого замечания приведены правило, путь, строки и наблюдаемое последствие. Отчёт обозначает пределы статической проверки. |

Каждая оценка содержит идентификатор критерия, статус, обоснование, точную цитату отчёта и хотя бы одну собственную квитанцию ревьюера. Сервер сверяет автора и попытку чтения, путь, SHA-256, диапазон строк и его покрытие аудитором. Для оценки `confirmed` все приведённые диапазоны должны иметь покрытие `covered`. При `discrepancy` обязательны исправление (`correction`) и способ проверки (`acceptanceTest`). Если есть хотя бы одно расхождение, рекомендация всего заключения — `needs_changes`. Если все оценки подтверждены — `confirmed`. Чтения ревьюера учитываются отдельно от карты аудитора. Смысл цитаты и достаточность доказательств оценивает ревьюер. [Валидатор заключения](../../../../packages/payload-task-manager/src/server/audit-review/conclusions/validateReviewConclusion.validator.ts) · [Общий порядок приёмки результата](../../../../.ai/templates/worker-assignment/TEMPLATE-WORKER-ASSIGNMENT-MANIFEST.md#приёмка-результата)

## Публикация и доставка

1. Runtime удостоверяет уже выданную попытку ревью и участника. Task Manager сверяет действующее назначение, независимость, доступ, проект, задачу, исполнение, итерацию, версии отчёта и карты. Отдельное основание приёмки закрепляет получателя, ревизию и отпечатки критериев и политики. До выдачи предметных строк сервер закрепляет это основание за попыткой. При каждом чтении и публикации сверяются исходное и действующее основания. Новая редакция критериев требует новой попытки.
2. В одной транзакции досье сохраняет неизменяемый результат с вердиктом `confirmed` либо `needs_changes` и событие доставки. Одно место результата принадлежит одной попытке. Совпадающий повтор возвращает сохранённую версию. Противоречащий повтор даёт конфликт.
3. Диспетчер доставляет ссылку во входящие уполномоченного оркестратора. Получение материалов требует действующего доступа. После сбоя между публикацией и доставкой диспетчер восстанавливает работу по сохранённому событию. Повтор доставки сохраняет единственную запись.
4. Отзыв прав, замена плана, несовпадение текущего основания или недоступные материалы останавливают зависимую операцию. Технический отказ сам по себе не является замечанием к аудиту. До устранения препятствия сохраняются существующие версии и решения.

## Решение и получатель доработки

| Действие оркестратора | Предпосылка | Что сохраняется |
| --- | --- | --- |
| Принять отчёт (`accept_audit`) | Все оценки и рекомендация имеют статус `confirmed`, список пунктов доработки пуст. Корректно описанное нарушение в коде совместимо с приёмкой отчёта. | Решение, автор, причина, ссылки на точные версии и основание. |
| Вернуть аудитору (`return_audit`) | Для каждого возвращаемого критерия со статусом `discrepancy` указаны исправление и способ повторной проверки. | Решение и адресованная работа по исходному назначению аудитора с указанием ожидаемой итерации. |
| Запросить уточнение у ревьюера (`clarify_reviewer`) | Требуется уточнение по конкретной оценке заключения. В решении указаны критерий, требуемое уточнение и способ проверки. | Решение и адресованная работа по назначению ревьюера. |

Решение и адресованная работа фиксируются атомарно. Перед записью повторно проверяются участник, доступ и версии основания и заключения. Совпадающий повтор возвращает прежнее решение. Из конкурирующих различных решений сохраняется одно. Версии отчёта, карты и заключения остаются доступны по правилам досье. После возврата исполнитель получает поручение из входящих. [Доработка и повторная приёмка](review-rework.md). Закрытие всей задачи определяется её политикой.

## Воспроизведение

Команда `npm run check:assignment:postgres -- conclusion` поднимает отдельный временный кластер PostgreSQL. Контракт проверяется детерминированными участниками. Границей этого среза служит сохранённое решение и, для доработки, доступная адресату запись. [Инструмент и порядок запуска](../../../../.ai/tools/worker-assignment/README.md#заключение-ревьюера-и-приёмка)

| Проверка на PostgreSQL | Наблюдаемый результат |
| --- | --- |
| Аварийное завершение издателя после commit и повторная доставка | Новый процесс доставляет сохранённое заключение один раз. Конкурирующие разные решения оставляют один результат. |
| Ошибка записи события или поручения внутри транзакции | Половина операции не сохраняется. После устранения сбоя повтор завершается успешно. |
| Подмена цитаты, пути, хеша, квитанции, диапазона или ссылки на ревизию | Зависимая операция отклонена. Независимые чтения не расширяют карту покрытия аудитора. |
| Смена критериев или политики до публикации либо решения | Исходная попытка сохраняет прежнее основание. Устаревшее заключение исчезает из ожидающих решения. |
| Отзыв явного разрешения либо членства Foundation | Выдача и запись проверяют текущие полномочия. Сохранённые результаты доступны участникам, сохранившим права. |
