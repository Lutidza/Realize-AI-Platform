# 9. Payload Admin interface

- **Статус:** target specification
- **Дата сверки реализации:** 10 сентября 2026 года

## 9.1. Информационная архитектура

`/admin/ai` является рабочим пространством управления задачами, а drawer и
contextual actions — дополнительными точками входа. Все они используют один
server-side policy и Change Engine.

Основные разделы:

- Conversations и Runs;
- Change Requests, approvals и risk;
- implementation diff/checks и preview;
- source promotion, releases, deployments и rollback;
- audit, usage и operator escalation;
- Integrations;
- AI Settings.

## 9.2. AI Settings

Раздел «Настройки → Агентский слой» находится по `/admin/ai/settings` и не зависит
от интеграции с конкретным провайдером. Целевой состав раздела:

- Skills;
- Knowledge;
- Prompt templates;
- Local rules;
- Roles и capability bindings;
- Check bindings;
- Agent profiles;
- Workflows;
- Evals;
- Configuration releases.

Admin редактирует draft installation overlay, запускает validation/evals,
сравнивает diff конфигурации и отдельно активирует immutable release. Интерфейс
не редактирует `.ai/**`, `.codex/**`, license/security policy или protected
server registry.

Workflow редактируется как декларативная типизированная схема. Он может
ссылаться только на prompt templates, check bindings и зарегистрированные
server capabilities из того же configuration release. Произвольные JS/TS,
shell-команды, SQL и executable-код не являются содержимым installation
workflow. Обязательные policy, approval и execution gates добавляются Change
Engine независимо от локальной схемы workflow.

Текущее состояние: persistence, aggregate Config API и рабочая область раздела
реализованы. Выбор черновика, создание пустого, копирование и серверная валидация
находятся в общей панели. Опубликованный черновик доступен для чтения и копирования.
Боковая навигация объединяет разделы по назначению:

| Группа | Разделы |
| --- | --- |
| Рабочая область | Обзор, Все записи |
| Агенты | Профили агентов, Роли |
| Инструкции | Навыки, Правила, Шаблоны инструкций |
| Выполнение | Рабочие процессы, Возможности, Проверки |
| Управление | Версии, Системная основа |

Общий каталог отображает все восемь поддержанных видов записей или один
выбранный вид. Доступны поиск по названию, ключу, виду и краткому содержимому,
фильтры включения и наличия входящих ссылок, сортировка по названию, ревизии
или числу входящих ссылок. На странице каталога — до 25 записей. Поиск,
фильтры, сортировка и страница хранятся отдельно для каждого каталога в текущей
рабочей области и сохраняются при открытии записи, возврате и смене раздела.

В «Все записи» создание начинается с выбора «Тип новой записи» и кнопки
«Создать запись». В отдельном каталоге доступно одно именованное действие:
«Новый профиль», «Новая роль», «Новый навык», «Новое правило», «Новый шаблон»,
«Новая возможность», «Новая проверка» или «Новый рабочий процесс».
При 512 записях и во время выполнения операции создание блокируется;
в черновике только для чтения действия создания отсутствуют.

Карточка показывает типизированное содержимое всех восьми видов, включая
инструкции, параметры и шаги рабочего процесса. Локальные правила поддерживают
создание, редактирование, отключение и удаление. Профили агентов, роли, навыки
и шаблоны инструкций, связи возможностей и проверок, рабочие процессы поддерживают
создание, копирование, редактирование и изменение состояния включения.
В карточках просмотра колонка
«Использует / Используется в» позволяет переходить между связанными записями
того же черновика. Связи определяются по паре `kind + key`:
повторы не удваивают счётчик, отсутствующие и выключенные цели остаются видимыми.
При наличии больше восьми связей доступен поиск по названию, ключу и типу.
Прямые и обратные списки имеют ограниченную высоту с прокруткой.
Ссылки на системные возможности и проверки показаны отдельно; возможность
разрешается по точным ID и версии. Эти сведения описывают структуру черновика,
а не применение конфигурации к запускам.

Форма профиля занимает всю ширину рабочей области. В ней редактируются название,
назначение, язык, состояние включения и ключ нового профиля. Ключ сохранённого
профиля изменить нельзя. Копирование открывает локальную форму с новым уникальным
редактируемым ключом; запись появится в черновике только после сохранения.

Семь сворачиваемых групп позволяют выбрать роли, навыки, правила, шаблоны
инструкций, рабочие процессы, связи возможностей и проверок того же черновика.
В каждой группе доступны поиск по названию и ключу, фильтр выбранных и страницы
по 25 записей; допускается до 128 связей каждого вида. Отсутствующие выбранные
цели показаны с предупреждением; для включённого профиля также отмечаются
выбранные выключенные записи. Такие ссылки можно явно исключить из выбора.
Рабочий процесс по умолчанию выбирается из выбранных
процессов и очищается при исключении соответствующего процесса. Переход к
связанной записи учитывает несохранённые изменения формы. Структурные ошибки
блокируют отправку. Предупреждения о целях связей не блокируют сохранение
черновика; семантическая проверка выполняется Config API при валидации
и создании выпуска.

Редактор роли содержит инструкции и выбор связанных возможностей. Роль описывает
обязанности агента и не задаёт права учётной записи Payload. У навыка дополнительно
редактируются назначение и условия применения (`triggerTerms`). У шаблона
редактируются текст, имена переменных и назначение (`slot`): инструкции агента,
планирование, рецензирование или шаг рабочего процесса. Под формой сохранённой
роли, навыка или шаблона показано, где используется запись; ссылки позволяют
проверить связанные объекты перед изменением или отключением.

Возможность связывается с точными ID и версией зарегистрированной системной
возможности. Проверка выбирается по ID серверного реестра. Выбор системных целей
и ограничений использует общий список с поиском, фильтром выбранных
и страницами по 25 вариантов. В форме возможности отдельно задаются действия,
области чтения и записи и лимит объектов. Неуказанные области наследуют SYSTEM;
пустой явный выбор запрещает соответствующие области. Пустой лимит наследует
системный, заданный должен быть положительным целым числом.

Сохранённые отсутствующие цели и значения видимы и не очищаются автоматически,
в том числе при смене системной возможности. Незавершённые связи можно сохранить
при корректной структуре полей; проверка черновика и компиляция профилей
остаются серверными. Под формами сохранённых возможностей и проверок доступно
их использование в других записях. Эти настройки не добавляют исполняемый код,
права учётной записи или подтверждение выполнения проверок.

Редактор процесса содержит общие сведения, выбор начального шага и лимит
от 1 до 64 шагов. В каталоге шагов есть поиск, фильтр типа, режим «Только требующие
внимания» и страницы по 25 записей. Поля выбранного шага открываются отдельно
от списка. Поддержаны ход агента, запрос ввода, возможность, проверка, условие
и завершение; переходы и связанные записи выбираются явно.

Входные параметры шага возможности представлены отдельным списком с поиском
и страницами по 25; редактируется один выбранный параметр. Источником значения
служат входные данные процесса, результат другого шага или заданное значение.
Текст, число, логическое и пустое значения имеют типизированные поля;
JSON вводится только для отдельного объекта или массива.

Новый ключ шага применяется действием «Применить ключ», одновременно обновляющим
начальный шаг, переходы и ссылки на результат. До применения или отмены
переименование остаётся несохранённым вводом и блокирует сохранение процесса.
Смена типа шага требует подтверждения замены его полей. Удаление учитывает
ссылки на шаг и показывает причину блокировки. Отсутствующие связи сохраняются
для исправления; структурно корректный незавершённый граф можно записать
в черновик. Полную проверку графа выполняет сервер при проверке черновика.

Сохранённые ключи ролей, навыков, шаблонов, связей и процессов неизменяемы.
Их копии получают уникальный ключ своего вида и остаются локальными формами до сохранения.
Копирование сохраняет содержимое и порядок списков исходной записи;
ссылки других записей не перенаправляются на копию автоматически.

«Версии» содержит поиск и страницы по 15 элементов для загруженных черновиков
и выпусков. Config API возвращает до 100 последних элементов каждого вида;
пагинация интерфейса работает в этом наборе и не является полной историей.
Выпуск открывается отдельно от изменяемого черновика: доступны его точный состав,
поиск, фильтры, переходы по записям и связям, исходная ревизия, совместимость
и manifest hash. Создание выпуска доступно для проверенного `ready` draft
без несохранённых изменений. Оно фиксирует immutable release и переводит
черновик в `released`, сохраняя его доступным для чтения и копирования.

Просмотренный выпуск активируется отдельным действием для новых запусков чата.
Для более раннего выпуска доступно «Вернуться к выпуску N»; сервер проверяет
совместимость и ожидаемую версию active pointer. Текущий активный выпуск
отмечен отдельно. Его номер — версия release, а версия pointer отражает число
переключений и не используется как номер выпуска. При неопределённом результате
создания или активации повтор сохраняет исходные body и `Idempotency-Key`;
после получения receipt повторяется только чтение подтверждённого результата.

«Системная основа» показывает фактические версию, профиль проекта, зарегистрированные
возможности с областями и ограничениями и идентификаторы проверок из bootstrap.
Содержимое `.ai/**` и `.codex/**` через эту проекцию не просматривается.

Все восемь редакторов используют общий жизненный цикл формы и сохраняют
остальные объекты, их ревизии и связи; удаление правила,
используемого профилями, блокируется. Несохранённые правки защищены при смене
черновика, уходе по ссылке и перезагрузке. Отмена Back/Forward внутри страницы
использует Navigation API там, где браузер разрешает отмену перехода;
в остальных случаях эта защита не гарантируется. Конфликт ревизии не
перезаписывает форму; повтор запроса после
неопределённого сетевого результата сохраняет его ключ идемпотентности.

В блоке ввода чата показываются профиль и выпуск следующего запуска. Список
профилей поддерживает поиск и страницы по 25 записей. При первом чтении
единственный доступный профиль выбирается автоматически и показывается по имени;
при нескольких профилях требуется выбор пользователя. Выбор сохраняется при
переносе диалога между панелью, страницей и отдельным окном. Обновление каталога
не заменяет устаревший выбор другим профилем; до нового выбора отправка недоступна,
а текст сообщения сохраняется. История показывает профиль и версию выпуска
сохранённого run, независимо от текущего active pointer.

Сохранение и валидация черновика не переключают конфигурацию чата. После активации
новые ответы используют профиль, роли, правила, навыки и прямые шаблоны
`agent_instructions`; уже созданные runs сохраняют свой снимок. База знаний
и evals пока отсутствуют. Декларативные workflows не исполняются;
ссылки capabilities/checks не предоставляют права и не являются
результатами проверок.

## 9.3. UX-инварианты

Для мутации UI показывает plan, scope, risk, стоимость, approvals, checks и
rollback strategy до исполнения. После исполнения — exact artifact, evidence,
preview и новое решение принятия. Disabled/blocked state должен объяснять
причину и не имитировать успех.
