# 3. Подтверждённые зоны риска, которые нужно перепроверить самостоятельно

Ниже перечислены наблюдения предварительного аудита. Не принимай их на веру: проверь каждый пункт по текущему состоянию ветки и зафиксируй evidence.

1. `documentation/architecture/project-structure.md` описывает `src/domain/**`, но фактическая реализация может находиться в других каталогах, включая `src/RealizeCore/**`.
2. В репозитории может одновременно существовать текущий `(app)` contour и экспериментальный/неактивный `_realize` contour.
3. Папки App Router с именем, начинающимся на `_`, имеют специальное значение и могут не образовывать публичный route segment.
4. `.codex/config.toml` заявляет Payload MCP на `/api/mcp`, но `src/payload.config.ts` может не регистрировать соответствующий endpoint/plugin.
5. Корневое приложение и `.ai/tools/agent-runtime` могут иметь несовместимые минимальные версии Node.
6. В корне используется npm lockfile, а Playwright web server может запускаться через `pnpm dev`.
7. Root TypeScript boundary может захватывать вложенные tool applications со своими tsconfig/path aliases.
8. В репозитории могут отсутствовать полноценные migrations, Dockerfile/Compose, CI workflow и реальные tests, хотя npm scripts/config files уже существуют.
9. Некоторые документы, на которые ссылается AI-layer, могут отсутствовать или быть несинхронизированными.
10. Лицензия `ISC` в `package.json` может не соответствовать будущей проприетарной коммерческой модели.
11. Могут присутствовать IDE/runtime artifacts, которые не должны входить в product source of truth.
12. Build ещё нельзя считать ни зелёным, ни сломанным, пока он не выполнен в корректном окружении с установленными зависимостями.
