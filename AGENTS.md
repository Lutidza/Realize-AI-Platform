**Realize — AI Platform**.

Рабочий слой ИИ-агентов:

- [.ai/](.ai/README.md) — проектные инструкции и инструменты агентов.
- [.ai-workspace/](.ai-workspace/README.md) — локальные материалы задач:
  референсы, скриншоты, логи и черновики.
- [.codex/](.codex/README.md) — настройки и процедуры Codex, адаптеры к `.ai/`.
- `.playwright-mcp/` — автоматически создаваемые снимки и логи Playwright MCP.
- [documentation/](documentation/INDEX.md) — продуктовые, архитектурные и
  эксплуатационные документы проекта.

Применяй инструкции в рамках указаний среды и задания пользователя. Отвечай
по-русски, кратко и по делу; технологии, команды, идентификаторы и пути
сохраняй в исходном виде.

## Порядок работы

1. При первом знакомстве прочитай [README](README.md) и
   [вход операционного слоя](.ai/README.md). Факты уточняй по относящемуся
   разделу [контекста проекта](documentation/project-context.md) и текущему коду.
2. Для проектной работы открой [общие правила](.ai/registry/rules/global/INDEX.md),
   затем профильные источники по таблице ниже. Прочитай применимые правила
   и checks; ссылка не требует рекурсивной загрузки всего графа документов.
3. До правки определи источник, владельца, существующие решения, границы
   и проверки по [основному workflow](.ai/workflows/core/main-delivery/WORKFLOW.md).
   Учитывай уже выданные полномочия; выполняй разрешённую задачу до результата.
4. Меняй правильный слой, сохраняя архитектуру, ограничения и чужие правки.
   Проверь результат по фактическому изменению и синхронизируй потребителей.
5. Сообщи результат, проверки, существенные пропуски и оставшиеся ограничения.

Обычный диалог требует только этого протокола. Анализ репозитория также требует
применимых источников, но не запускает стадии изменения и доставки.
Уже прочитанные актуальные документы повторно не загружай; роли определяют
ответственность и сами по себе не требуют отдельных агентов.

Команды проекта и AI tooling запускай из корня обычными `node`, `npm` и `npx`
в окружении с закреплённой парой Node/npm. Проверка: `npm run verify:runtime`.
Выбор окружения при запуске терминала, IDE, Codex, MCP или службы описан
в [README](README.md#локальный-запуск)
и [правиле зависимостей](.ai/rules/development/RULE-DEPENDENCY-VERSION-EVIDENCE-BEFORE-INSTALL.md#единый-runtime-проекта).

Когда задача требует ожидания команды или воркера, следуй
[правилу ожидания](.ai/rules/worker-runtime/RULE-WORKER-CONTEXT-BUDGET-AND-REUSE.md#ожидание-процессов-и-воркеров):
событие завершения либо длительное ожидание того же handle, без частых пустых опросов.

Обсуждение, объяснение и совместное планирование остаются в диалоге IDE.
Для порученной работы передай исходный текст оркестратору через Realize MCP
`task_submit` (поля `task` и `idempotencyKey`). Создай один ключ на поручение.
При потере ответа на submit повтори тот же текст с тем же ключом.

- По умолчанию сразу верни `runId` и статус из ответа `task_submit` в **итоговом
  сообщении** и заверши ход. Следующий вопрос пользователя обрабатывай независимо.
- По запросу о статусе или результате один раз вызови `task_get` для нужного
  `runId`, сообщи текущее состояние и доступный отчёт и заверши ход.
- Только по явной просьбе дождаться результата сообщи `runId` и ожидай
  завершения этого запуска по правилу ожидания выше.

При статусе `blocked` передай причину из отчёта и заверши поручение без
повторной выдачи или самостоятельного поиска.
Оркестратор подбирает материалы и выдаёт Assignment.
Диалоговый агент не запускает исполнителей напрямую, в том числе через CLI.
При недоступном маршруте сообщи о препятствии. Статическое чтение выполняет аудитор.
Для правки по тексту оркестратор сам ищет источники и предлагает точные
операции. При фазе `awaiting_write_approval` в отчёте `task_get` покажи
пользователю операции, пути и причины. Только после его явного согласия
подтверди показанный SHA-256 через [approve-write](.ai/tools/worker-assignment/README.md#назначение-правки).
Отчёт с проверенным diff доступен по исходному runId. Для переноса в рабочую
копию получи отдельное подтверждение пользователя на показанный diff. Свяжи его
SHA-256 с тем же runId командой `approve-apply` и читай результат через `task_get`.
Для Git-доставки вызывающая среда связывает явное разрешение пользователя с runId
по [контракту очереди](.ai/tools/worker-assignment/README.md#назначение-git-доставки).
Для добавления одного файла в индекс вызывающая среда до submit закрепляет его путь через
`ai:assignment:ide -- authorize-stage`. Оркестратор выдаёт Git-воркеру только `manage/stage-file`.
Полный add в составе commit и отдельный push имеют собственные назначения.

## Git-воркер

Основной агент читает Git workflow до запуска. Development `inspect` выполняет
отдельный программный адаптер через прежний `git:worker -- inspect`, без модели
и Codex App Server. Остальные действия, включая читающий `manage`, выполняет
отдельный Git-воркер: он использует этот протокол и правила выбранного действия;
архитектуру изучает только при отдельной задаче разработки. Подключённые
ограниченные модельные воркеры получают только
[commit](.codex/prompts/workflows/delivery/git/commit.md),
[push](.codex/prompts/workflows/delivery/git/push.md),
[manage](.codex/prompts/workflows/delivery/git/manage.md),
[fetch](.codex/prompts/workflows/delivery/git/fetch.md),
[pull](.codex/prompts/workflows/delivery/git/pull.md) или
[merge](.codex/prompts/workflows/delivery/git/merge.md), без AGENTS и общих документов.
Границы исключения определены [Git-правилом](.ai/rules/git/RULE-GIT-DELIVERY.md).

## Ограничения и конфликты

- Не раскрывай реальные секреты и не записывай их в файлы или Git.
- Generated-файлы обновляй через источник и штатный генератор.
- Не имитируй команды, проверки, загрузку инструкций или работу других агентов.
- Commit, push и deployment выполняй только в разрешённой области;
  завершение правки само по себе не разрешает эти действия.
- `.codex` не вводит отдельные проектные правила. Target spec, история и отчёт
  не доказывают реализацию; фактическое состояние сверяй с кодом и документацией.
- При неразрешимом конфликте назови конкретные источники и недостающее решение.
  Останови зависимое действие и продолжай независимую разрешённую работу.
